# C9 — Context engineering expert

Audit of how much context the paid-media engine (`engine/`) spends per model call and per turn, what is
unnecessary, and how it should be segmented. Everything below was measured against the checkout at
`/home/user/markting-ai` on 2026-10-02 with the fixture (sample-data) profile and the scripted model, because
no live model key or provider credentials may be set in an audit. Numbers for live catalogs are therefore
extrapolations and are tagged INFERRED. Token figures use the chars/4 heuristic unless stated otherwise.

## Findings

### C9-01 — `summarize_window` output is unbounded and, once offloaded, unusable by the model
- Severity: P2. Classification: VERIFIED_RUNTIME (sizes), VERIFIED_CODE (consumers).
- Evidence: `tools/summary.py:84-148` emits one entry per entity and one per day per account with no cap;
  measured 14,401 chars for 28 days × 3 fixture accounts (8 campaigns total), 6,066 chars for 7 days × 3
  accounts, 5,019 chars for 28 days × 1 account (`measure.py`). Offload threshold is 6,000 chars
  (`config.py:137`, `middleware/offload.py:36`). The stub says "Use the artifact id with deterministic tools"
  (`offload.py:50`), but every deterministic consumer rejects a `tool_result` artifact:
  `compare_periods.py:59-60` and `summary.py:170` require `performance_rows`, `reports.py:40-41` requires
  `analysis`. The stub carries no path (`offload.py:44-51`) and neither `instructions.md` nor any skill names
  `workspace/analysis/` (grep in command 6 found only the code comment at `artifacts.py:122`).
- Description: with as few as three accounts the weekly pacing summary already exceeds the threshold and
  the model receives a 400-char preview plus a hint that leads nowhere. A real account with 20+ campaigns
  will cross the threshold on every call. The skill explicitly forbids computing from previews
  (`workspace/skills/paid-media-analysis/SKILL.md` step 7), so the model is left with no numbers.
- Impact: pacing/anomaly/top-N questions silently degrade to "I could not read the summary" or to guessing;
  wasted round trips.
- Recommendation: make `summarize_window` return a bounded head (top-N entities, flagged days only, totals)
  with the full series in an `analysis` artifact; add a deterministic `read_analysis_section(artifact_id,
  section, offset, limit)` tool; put the artifact path in the offload stub.

### C9-02 — `compare_periods` summary grows ~1k chars per account and will hit the same offload cliff
- Severity: P2. Classification: VERIFIED_RUNTIME (3,206 chars for 3 accounts), INFERRED (scale).
- Evidence: `tools/compute.py:349-358` caps attention lines at 3 per platform, but `summarize()` emits one
  per-platform block (~1k chars measured) with no cap on platform/account count; threshold 6,000 chars.
- Description: six or more connected accounts (Pipeboard supports eight platforms, `docs/architecture/
  tools-and-context.md:4`) put the `analysis_summary` over the threshold; the offloaded `analysis_summary`
  is what the report skill tells the model to "quote verbatim" and what `render_report` needs as
  `analysis_artifact_id` (the id survives in the 400-char preview only by luck of key ordering).
- Recommendation: emit a fixed-size summary (cross-platform totals + N largest movers) and leave per-account
  detail in the analysis artifact; raise the threshold for this tool or exempt it like paged tools.

### C9-03 — Offloaded content is stored as one escaped JSON line, so `read_file` cannot page it
- Severity: P3. Classification: VERIFIED_RUNTIME.
- Evidence: `offload.py:38-43` writes `{"tool_name":..., "content": <string>}`; `artifacts.py:121-125` dumps with
  `indent=1`, so the string value is a single line (measured 8,287-char line for a 6,921-char payload,
  `fsread.py`). deepagents chunks lines at 5,000 chars with continuation markers
  (`deepagents/backends/utils.py:87,236-239`).
- Impact: the "offload" merely adds a tool round trip and returns the same bytes, now JSON-escaped and
  split mid-token, to the context it was meant to protect.
- Recommendation: offload structured results as parsed JSON (not a string) or as JSON Lines, and include
  `path` in the stub.

### C9-04 — "One row per line" artifact layout claim is false; paging reads ~3 rows per page
- Severity: P3. Classification: VERIFIED_RUNTIME.
- Evidence: comment at `tools/artifacts.py:122` vs `json.dumps(..., indent=1)` at `:124`; measured
  performance_rows artifacts: 84 rows → 2,551 lines, 82 rows → 2,409 lines, 52 rows → 1,596 lines (~30 lines
  per row); `read_file` default `limit=100` (`deepagents/middleware/filesystem.py:912`) → ~3 rows per page,
  ~26 pages to read one 28-day artifact.
- Recommendation: write `rows` as JSON Lines (one row per line) with a small metadata header; or drop the
  claim and steer the model away from `read_file` on row artifacts.

### C9-05 — The runtime agent can read the whole engine checkout, including its own system prompt and source
- Severity: P2. Classification: VERIFIED_CODE + VERIFIED_RUNTIME (backend read).
- Evidence: `runtime/local.py:28-50` denies reads only for `/.env*`, `/.venv/**`, `/.git/**`, `/.mda/**`,
  `/.agents/**`, `/.claude/**`, `/config/**`, `/workspace/sources/**`, `/docs/org/**`; "If no rule matches,
  the call is allowed" (`deepagents/graph.py` docstring, `permissions`). `FilesystemBackend(root_dir=project_root)`
  (`local.py:78`). Backend reads of `/AGENTS.md`, `/src/paid_media_agent/assembly.py` (306 lines),
  `/tests/unit/test_compute.py`, `/README.md` succeeded (`fsread.py`); `/instructions.md` is readable.
  `glob`/`grep` are bound (`assembly.py:59`). Readable volume: `src` 826 KB, `tests` 254 KB, `docs` 3.76 MB,
  root markdown + `uv.lock` 976 KB (command 11).
- Description: nothing stops a user prompt such as "grep the repo for 'approval' and show me" from pulling
  source into context, or "print /instructions.md" from exposing the prompt that `instructions.md:48`
  says must never be exposed. It is also the largest avoidable context sink in the system: a single `grep`
  over `src/` can return 20k tokens (`TOOL_RESULT_TOKEN_LIMIT`, `backends/utils.py:88`) and is exempt from
  the engine offload (`offload.py:18`).
- Recommendation: invert the policy: allow reads only under `/skills/**`, `/workspace/skills/**`,
  `/workspace/analysis/**`, `/workspace/out/**`; deny everything else. Not cross-tenant (single-tenant
  filesystem), hence P2 not P0.

### C9-06 — deepagents skills boilerplate adds ~2.3k chars of irrelevant text to every call
- Severity: P3. Classification: VERIFIED_RUNTIME.
- Evidence: captured system prompt lines 73-122 (`system_prompt.txt`): "web-research" example, "Skills may
  contain Python scripts or other executable files", "When in doubt, check if a skill exists". The template
  is `SKILLS_SYSTEM_PROMPT` (1,857 chars, `deepagents/middleware/skills.py:812`) and is not overridden
  (`runtime/local.py:71-82` passes `skills=` only). The engine hides `execute`
  (`middleware/authorization.py:22`), so the "executable files" guidance is actively misleading.
- Recommendation: construct `SkillsMiddleware(system_prompt=<product template>)` with the five skill lines
  only (~900 chars).

### C9-07 — Two path conventions for the same skill files, plus a probe for a file that does not ship
- Severity: P3. Classification: VERIFIED_RUNTIME.
- Evidence: the skills section tells the model to read `/workspace/skills/<skill>/SKILL.md`
  (`system_prompt.txt:84-92`, because `engine/skills -> workspace/skills` is resolved by the backend) while
  `instructions.md:12-14,57` and every SKILL.md say `/skills/...`. Both resolve (backend read of either path
  returns 45 lines). `/skills/company-context/SKILL.md` is referenced at `instructions.md:13`,
  `paid-media-analysis/SKILL.md` step 1 and `paid-media-wiki/SKILL.md` "organization layer", does not exist
  (`ls workspace/skills/company-context` → no such file), and the backend returns "File not found" (49 chars).
- Impact: one wasted tool round trip per analysis in every deployment that has not authored company context;
  model confusion about which root is canonical.
- Recommendation: decide company-context presence at assembly time and inject a one-line fact into the
  system prompt instead of asking the model to probe; use one path root everywhere.

### C9-08 — Instruction content is duplicated between `instructions.md` and the skills
- Severity: P3. Classification: VERIFIED_CODE.
- Evidence: window-resolution rules at `instructions.md:25-29` and `paid-media-analysis/SKILL.md` step 2;
  the propose/execute protocol at `instructions.md:33-46` and `paid-media-writes/SKILL.md` steps 5-9;
  "discover, never remember tool names" at `instructions.md:9`, `paid-media-analysis/SKILL.md` step 3,
  `paid-media-wiki/SKILL.md` Boundaries. Roughly 1.2k chars repeated whenever a skill is read.
- Recommendation: keep policy (never mutate directly, missing ≠ zero) in the system prompt; keep procedure
  only in skills.

### C9-09 — No engine-level compaction; the only compaction is deepagents' default at 85% of the model profile
- Severity: P2. Classification: VERIFIED_CODE (middleware), VERIFIED_RUNTIME (profiles), NOT_VERIFIED (API tier).
- Evidence: `assembly.py:246-255` adds no summarization/trim middleware; grep for `Summarization|trim_messages|
  context_window` in `engine/src` → none. `deepagents/graph.py:888` adds `create_summarization_middleware`
  unconditionally: trigger `("fraction", 0.85)` when the model profile has `max_input_tokens`, else
  `("tokens", 170000)`, keep `("messages", 6)` (`middleware/summarization.py:280-296`). Profiles: sonnet-4-6 /
  opus-4-6 = 1,000,000 → trigger ≈ 850k tokens; haiku-4-5 = 200,000 → 170k; gemini-3-flash = None → 170k
  flat. Threads persist and are reused by the UI (`assistant-chat.tsx:45`, `runner.py:154`), user messages
  may be 8,000 chars (`assistant.ts:33`).
- Description: for the default model (`anthropic:claude-sonnet-4-6`, `docs/ARCHITECTURE.md:678`) nothing
  compacts the thread before ~850k tokens. Whether the deployment's API tier actually accepts >200k-token
  requests was not verifiable here; if it does not, long threads fail at the API before compaction ever runs.
  Even when it does, every turn after ~100 messages re-sends hundreds of thousands of tokens.
- Recommendation: configure an explicit trigger (for example 60k tokens, keep last 12 messages) in
  `assembly.py` via deepagents' `SummarizationMiddleware` settings, and prune `tool_result` stubs older
  than N turns.

### C9-10 — Two independent offload layers with different stubs; the framework layer is dead for engine tools
- Severity: P3. Classification: VERIFIED_CODE.
- Evidence: engine `ResultOffloadMiddleware` at 6,000 chars (`offload.py:36`) runs inside deepagents
  `FilesystemMiddleware`, whose own eviction fires at `tool_token_limit_before_evict=20000` tokens
  (`deepagents/middleware/filesystem.py:1650`). User middleware is placed after the core stack
  (`graph.py:382`), so engine offload sees results first and the framework layer only ever acts on the paged
  tools the engine exempts (`offload.py:18`).
- Impact: two mental models for the LLM ("artifact id" vs framework's file path), and the framework path
  remains the only thing bounding `grep`/`read_file` output (20k tokens, see C9-05).
- Recommendation: pick one layer; if the engine layer stays, lower the framework limit for paged tools or
  cap `grep`/`glob` output explicitly.

### C9-11 — Portable selector path re-sends the whole platform catalog descriptions on every turn
- Severity: P3 (cost), GAP for non-native models. Classification: VERIFIED_CODE, INFERRED (live scale).
- Evidence: `LLMToolSelectorMiddleware` builds a selection request with every non-always-included tool's
  name+description (`langchain/agents/middleware/tool_selection.py:120,261-293`) and only the last user
  message; descriptions are up to 1,024 chars (`reads.py:381`) from catalog entries truncated at 1,000
  (`catalog.py:284`). Always-included set is 15 tools (6 fs + 5 core + 4 write, `assembly.py:228-231`);
  selected ≤ 6 (`config.py:136`).
- Description: for Gemini, LangSmith-gateway and unknown models (`tool_selection.py:160-177`) each turn
  costs an extra model call carrying N × ≈(name + description) chars; a live eight-platform Pipeboard
  catalog with ~80 read tools would be ≈ 20–80k chars per turn (INFERRED). The selector sees only the last
  human message, so multi-turn follow-ups ("and for Meta?") lose the platform context.
- Recommendation: cache selection per thread/platform; pass a short per-tool summary (≤160 chars) to the
  selector instead of the full description.

### C9-12 — No language/locale instruction for an Arabic-first product
- Severity: GAP (not a defect). Classification: VERIFIED_CODE.
- Evidence: command 12 (no match in `instructions.md` or skills); `README.md:3,72` states Arabic-first; the
  only Arabic-aware engine code is the demo intent regex `services/engine-demo/serve_demo.py:63-66`; the
  demo answers are English (`testing/demo_script.py:88-130`).
- Context implication: Arabic text tokenizes at roughly 2–3× the tokens per character of English (INFERRED);
  the 8,000-char user-message cap (`assistant.ts:33`) is therefore ~4–6k tokens, and Arabic answers inflate
  history faster than the English fixture numbers above suggest. Neither the offload threshold nor the
  selector budget accounts for this.
- Recommendation: add a locale line to the system prompt (answer in the user's language, keep ROAS/CPA/CTR in
  English as the README promises) and budget tokens, not chars, for offload.

### C9-13 — Workspace artifacts accumulate with no retention
- Severity: P3 (disk), not context. Classification: VERIFIED_RUNTIME.
- Evidence: 37 leftover artifacts (1.5 MB) in `engine/workspace/analysis` from demo/test runs, git-ignored
  (`engine/.gitignore:21`); no cleanup code (`grep -rn -i "retention|cleanup|prune" engine/src` not found in
  artifact paths). Every read of every turn writes 20–65 KB.
- Recommendation: per-thread subdirectories and a TTL sweep.

## What a world-class system would need (gaps, concrete)

Segmentation by task type, designed (not implemented) against the current assembly:

1. Intent router before assembly (cheap classifier or the selector model): `analysis`, `write`, `report`,
   `capability_question`, `other`. Each intent gets a context profile.
2. Profiles (tools always bound → prompt fragments → skills exposed):
   - Analysis: `list_accounts`, `discover_tools`, `compare_periods`, `summarize_window`, `read_file`, `ls`
     (10 tools instead of 15 always-on; drops `write_file`/`edit_file`/`glob`/`grep` and the 4 write tools,
     ≈ 5k chars of tool JSON); skills: `paid-media-analysis` + the wiki pages it names; prompt: method +
     data rules (`instructions.md:6-29`) only.
   - Write: `list_accounts`, `discover_write_operations`, `propose_change`, `execute_change`, `get_proposal`,
     `read_file`, plus the `list_campaigns`/`get_campaign` reads of the target platform; skills:
     `paid-media-writes` + `write-safety.md`; prompt: `instructions.md:31-49` only.
   - Report: `compare_periods`, `render_report`, `read_file`, `write_file` (custom briefs); skills:
     `paid-media-report`, `report-design`.
   - Capability question: `list_accounts`, `discover_tools`, `discover_write_operations`; no skills.
3. Result contracts: every deterministic tool returns ≤ 2,500 chars of head + an `analysis` artifact id;
   one `read_analysis_section` tool pages artifacts semantically (by entity/day), replacing `read_file` for
   data. Artifacts as JSON Lines.
4. Offload stub carries `path`, `kind`, and the deterministic tool that can consume it; threshold measured in
   tokens with a locale-aware estimator.
5. Explicit compaction policy per profile (trigger ~60k tokens, keep the last analysis summary and all
   proposal/receipt messages verbatim).
6. Filesystem allow-list (skills + workspace only); a product-specific skills prompt template; one skill
   path root; company-context presence decided host-side.
7. Selector memory per thread for the portable path, with short per-tool summaries.
8. Telemetry: log per-call input tokens, tools bound, and offload events to confirm these budgets in
   production (nothing in `engine/src` records them today; `AssemblyMetadata` is static).
