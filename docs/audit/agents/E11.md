## Disagreement resolved
**Engine reports IDOR severity.** E1-01 and E5-01 rated it **P1**; E4-01 and E10-02 rated it **P2 today,
latent P0**. I resolved to **P1 (latent-P0)** against code: the `/reports` + `/reports/files/{name}`
endpoints are served only by `services/engine-demo/serve_demo.py`, which is boot-pinned to synthetic
`sample` data (so today only run metadata + identical fixtures + a global 50-entry eviction cap cross
tenants), **but** the two *platform* routes carry zero org scoping and are production code; nothing
prevents a real-data report host from being wired to the same unscoped routes, and the product is sold
as multi-tenant SaaS over real ad data. P1 attaches to the un-isolated route (the real defect), not to
the demo pin (an incidental mitigant); P0 is reserved for when real tenant data actually crosses. The
other merge was E2-01 (P1) + E1-02 (P2) into SEC-06 (P1): the combined grant-lifecycle gap — no admin
kill switch, survives deprovisioning, 30-day refresh, budget-spend blast radius — justifies P1.
