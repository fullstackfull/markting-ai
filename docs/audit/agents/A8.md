# A8 — Microsoft Ads expert

Audit question: can MARKTING-AI understand and manage Microsoft Advertising like an expert media buyer, or does it merely have a connector? Repository code is the source of truth; every document claim below was checked against code.

Headline: the Microsoft provider is an **unmodified upstream adport package** (single import commit `fa7bf19`, no edits listed in `UPSTREAM.md`). It is a thin, well-gated, campaign-level connector: account + campaign discovery, one async Summary-aggregated campaign report with 5 raw columns, three typed writes (create Search campaign, pause/activate, daily budget) and three generic passthrough writes. **The AI engine (`engine/`) and the markting bridge have no Microsoft platform at all**, so nothing the "AI media buyer" does can read, analyse or propose changes on Microsoft Advertising. Everything an expert needs day to day (ad groups, keywords, ads, bids, breakdowns, pacing, search terms, quality score, conversion goals, auction insights) is either reachable only through raw passthrough with no server validation, or missing.

## Findings

### A8-01 — Generic `microsoft_api_create` does not enforce paused creation when `Status` is omitted
- Severity: **P1** (potential live delivery of newly created ads/keywords despite `paused_creation` policy)
- Classification: VERIFIED_CODE (the gap) / NOT_VERIFIED (Microsoft's server-side default per entity)
- Evidence: `platform/packages/microsoft/src/provider.ts:526-535` — `coerceMicrosoftCreatedStatuses` only rewrites a key `Status` whose value is exactly `'Active'`; it never injects `Status: 'Paused'` when the key is absent. `platform/packages/microsoft/src/tools.ts:346` advertises "Active statuses are forced to Paused". `platform/packages/core/src/policy/policy.ts:176-177` defines the policy as "Created campaigns/ad groups/ads are coerced to PAUSED". Test `platform/packages/microsoft/test/microsoft.test.ts:264-281` only covers the explicit-`Active` case.
- Description: The typed `microsoft_create_campaign` path is safe because it always sets `Status` explicitly (`provider.ts:365-377`). The generic path relies on Microsoft's per-entity default. For Ads and Keywords added under an already-active ad group, Microsoft Advertising's documented default is Active (NOT_VERIFIED offline; the tool text at `tools.ts:315` itself only asserts "The API's own default status is Paused" for campaigns). A body like `{AccountId, AdGroupId, Ads:[{...}]}` with no `Status` sails through preview with `coercions: []`.
- Impact: the strongest safety rail in the system (`paused_creation`) is bypassable by omission on the generic path, which is also the only path to create anything below campaign level.
- Recommendation: in `coerceMicrosoftCreatedStatuses`, inject `Status: 'Paused'` into every element of known collection arrays (`Campaigns`, `AdGroups`, `Ads`, `Keywords`, ...) when absent, record the coercion, and add a test for the omitted-status case.

### A8-02 — Reporting results are unreachable through `microsoft_api_read`; docs claim "covers reporting operations"
- Severity: **P2**
- Classification: VERIFIED_CODE
- Evidence: `platform/packages/microsoft/src/provider.ts:488-498` — `validateMicrosoftReadPath` admits only actions starting `Query|Search|Get|Submit|Poll`; `provider.ts:122-132` always issues POST to the v13 host; there is no tool exposing `client.download()` (`client.ts:114-120`). `platform/docs/providers.md:19`: "`microsoft_api_read` covers query, search, get, and reporting operations".
- Description: an agent can `GenerateReport/Submit` and `GenerateReport/Poll` and will receive a `ReportDownloadUrl`, but nothing lets it fetch, unzip or parse the file. The only parsed report is the hard-coded campaign Summary report in `report()`.
- Impact: every expert report (keyword, search-query, ad, geo, device, age/gender, hourly, audience, share-of-voice, conversion-goal) is non-functional through the AI surface despite documentation claiming coverage.
- Recommendation: add a `microsoft_report` tool that runs Submit→Poll→download→unzip→parse for any documented `*ReportRequest` type with chosen `Columns`/`Aggregation`, returning rows; or at minimum document the limitation.

### A8-03 — Customer-management reads let a workspace member enumerate accounts outside the enabled-account scope
- Severity: **P2** (same-tenant information disclosure; defeats the cloud's account-scope control)
- Classification: VERIFIED_CODE
- Evidence: `tools.ts:289` allows `service: 'customer'`; `provider.ts:512-524` `validateMicrosoftAccountScope` only inspects keys named `AccountId`/`AccountIds`; `Accounts/Search` and `Customers/Search` bodies use `Predicates:[{Field,Operator,Value}]` (`provider.ts:86-89` shows the shape) and pass. `platform/apps/cloud/lib/cloud/account-scope.ts:36-56` authorises only the `account_id` argument; `account-scope.ts:68-72` comments "Never enumerate an entire grant just to service a routine ... request" — but `microsoftTools(provider)` receives the **unwrapped** provider (`runtime.ts:125-126`).
- Description: with `microsoft_api_read {account_id:<enabled>, service:'customer', path:'Accounts/Search', body:{Predicates:[{Field:'UserId',Operator:'Equals',Value:'<id>'}],PageInfo:{Index:0,Size:1000}}}` a member lists every account in the OAuth grant, including ones the admin deliberately left disabled. Not cross-tenant (same org grant).
- Recommendation: restrict `service:'customer'` paths to a short allowlist (e.g. `User/Query`) or route them through the `AccountScopedProvider`, and filter results to enabled accounts.

### A8-04 — AI engine and markting bridge have no Microsoft Advertising platform
- Severity: **GAP** (not a defect — nothing claims otherwise in code; root README/docs list Microsoft as a supported platform of the product)
- Classification: VERIFIED_CODE
- Evidence: `engine/src/paid_media_agent/domain/common.py:12-33` — `Platform` enum has no Microsoft/Bing member; `PIPEBOARD_PLATFORMS` has none; `engine/src/paid_media_agent/config.py:140-147,232-241` — no Pipeboard endpoint; `engine/src/paid_media_agent/tools/fixtures.py:27-42` — fixtures only for `GOOGLE_ADS`/`META_ADS`; `engine/src/paid_media_agent/tools/normalize.py:15-22` — spend-field map only for Google/Meta/LinkedIn; `engine/src/paid_media_agent/tools/direct/` holds only `openai_ads.py`, `x_ads.py`; `engine/config/write-policy.example.toml` admits only google/meta/reddit operations; `platform/apps/cloud/lib/markting/translate.ts:12-15,19,72-74` — `ENGINE_PLATFORMS` and `PLATFORM_TO_PROVIDER` omit Microsoft.
- Impact: the "AI media buyer" cannot read Microsoft data offline (fixtures) **or** online (Pipeboard/direct), cannot run compare-periods/anomaly analysis on it, and cannot propose Microsoft changes to the approvals bridge. Microsoft exists only as an adport MCP/CLI/dashboard connector.
- Recommendation: add `MICROSOFT_ADS` to the engine `Platform`, a direct adapter in `tools/direct/` (there is no Pipeboard Microsoft MCP configured), fixtures + normalize spend map, and the bridge mapping `microsoft_ads → 'microsoft'` with `update_campaign_budget/status` → `microsoft_set_budget/microsoft_set_campaign_status`.

### A8-05 — Bid changes via `microsoft_api_update`/`microsoft_api_create` are not policy-checked
- Severity: **P2** (financial risk; preview is client-side only)
- Classification: VERIFIED_CODE
- Evidence: `provider.ts:312-328` rejects bodies matching `/budget/i` but has no check for `CpcBid`, `Bid`, `Amount`, `BiddingScheme`, `TargetCpa`, `TargetRoas`, `MaxCpc`; `provider.ts:543-561` `collectMicrosoftBudgets` only captures `/budget/i` keys, so `PolicyEngine.checkBudgetPolicy` (`core/src/policy/engine.ts:133-153`) sees no delta. `capabilities()` returns `serverDryRun: false` (`provider.ts:53-55`) and `previewWrite` returns `serverValidated: false` (`provider.ts:263`).
- Description: `{resource:'Keywords', body:{AccountId, AdGroupId, Keywords:[{Id, Bid:{Amount:500}}]}}` passes with a preview that is just the echoed JSON. No current-value fetch, no percent cap, no absolute cap.
- Recommendation: typed `microsoft_set_bid`/`microsoft_set_bidding_scheme` tools that fetch current values and emit deltas; reject raw bid keys in the generic update like budgets are rejected.

### A8-06 — Account discovery is capped at 100 and silently truncates
- Severity: **P2** for agency/MCC tenants, P3 otherwise
- Classification: VERIFIED_CODE
- Evidence: `provider.ts:86-89` `PageInfo: { Index: 0, Size: 100 }`, no loop over pages, no `truncated` signal.
- Impact: accounts beyond the first 100 are invisible to `accounts_list`, the cloud Accounts page and `scopeFor()`; a write to such an account would send `CustomerId` header undefined (`provider.ts:105-108`).
- Recommendation: page until `Accounts.length < Size` (Microsoft allows Size up to 1000).

### Writes and gating
All six write tools (`microsoft_create_campaign`, `microsoft_set_campaign_status`, `microsoft_set_budget`, `microsoft_api_create`, `microsoft_api_update`, `microsoft_api_delete`) are `guardedWriteTool` → `PolicyEngine` (VERIFIED_CODE `tools.ts:310-367`, `core/src/tools/write.ts:334-387`). `applyWrite` is reached only from `PolicyEngine.apply` after hash/TTL/provider match (`engine.ts:87-125`). `standardActions().pauseCampaign` routes audit recommendations to the guarded status tool (`provider.ts:57-64`, tested `test:109-115`).

### Server-validated vs client-side preview
Nothing is server-validated: `capabilities().serverDryRun === false`, `previewWrite().serverValidated === false` (`provider.ts:53-55,263`). Previews are stringified request bodies (`provider.ts:305,323,338`) or before/after lines built from a fresh `Campaigns/QueryByAccountId` (`provider.ts:426-427,450-451`). Microsoft v13 offers no validate-only mode, so this is a platform constraint, but it means malformed ad copy, policy violations and bid errors surface only at apply time as `PartialErrors`.

### Test coverage of wire formats
Covered (VERIFIED_TEST, `microsoft.test.ts`): token refresh + rotation + 4 headers (61-73); sandbox host/token (75-82); fault formatting (84-96); CSV quoting (99-106); GetUser/SearchAccounts predicate (117-127); report Submit body/date struct/Poll/zip/CSV→metrics (129-165); AddCampaigns POST shape + Paused + `DailyBudgetStandard` (167-195); UpdateCampaigns PUT `{Id, DailyBudget}` + shared refusal (197-250); passthrough read headers (252-262); generic create coercion + budget delta (264-281); cross-account/budget rejections (283-292); DELETE only on apply (294-308). Cross-package: MCP surface registration (`mcp/test/provider-surface.test.ts:28-62`), UI change-line rendering (`mcp/test/ui.test.ts:416`), cloud OAuth URL/scope/PKCE and hydrate (`cloud/test/provider-oauth.test.ts:77-81,112`), DB round-trip (`cloud/test/database.integration.test.ts:260-275`, DB-gated).

No test for: account-level aggregation (`aggregateAccountRows`), Poll `Status: 'Error'`, poll timeout, `Success` with null URL, empty zip, missing CSV columns, `ReportDownloadUrl` download failure, `>100` accounts, `scopeFor` miss, 117 handling, `microsoft_api_update` happy path (PUT through generic), `microsoft_api_create` with omitted `Status` (A8-01), `Accounts/Search` via passthrough (A8-03), `resolveMicrosoftCredentials` env/store precedence, `extractMicrosoftIds` on nested results, CSV BOM/locale numbers.

## What a world-class system would need (gaps, concrete)
1. Engine platform `microsoft_ads` with a direct adapter (no Pipeboard MCP exists), fixtures, normalize spend map, write-policy rows and bridge mapping (A8-04).
2. A general `microsoft_report` tool (any `*ReportRequest`, `Columns`, `Aggregation: Daily/Hourly`, `ReportTimeZone`, completeness flag) and typed convenience reports: keyword, search-query (negatives), ad/RSA asset, geo, device, age/gender, hour-of-day, audience, share-of-voice (impression share, lost IS budget/rank), conversion-goal (A8-02, A8-07).
3. Typed reads: ad groups, keywords (with QualityScore, ExpectedCtr, AdRelevance, LandingPageExperience), ads with editorial status, negative keywords, audiences/associations, conversion goals and UET tags, shared budgets, bid strategies, change history.
4. Typed writes with current-value fetch and policy deltas: keyword/ad-group bids and bid adjustments (device, location, audience), bidding scheme changes (Manual CPC ↔ Enhanced CPC/MaxConversions/TargetCpa/TargetRoas), negative keyword adds, ad group/ad/keyword status, shared-budget amount, campaign languages/locations (A8-05).
5. Pacing: MTD spend vs `DailyBudget × days`, `BudgetPaused` detection and "limited by budget" alerts; Microsoft-specific anomaly rules (QS drop, IS lost-to-budget spike, editorial rejection, search-term waste).
6. Google Ads import/sync awareness (campaigns imported from Google have `CampaignType` and settings that must not be edited in Microsoft).
7. Operational hardening: paging accounts (A8-06), persisted `ParentCustomerId` (A8-08), 117 backoff and longer/adaptive poll (A8-09), fault-code UX mapping (A8-10), Arabic-market defaults (time zone, currency SAR/AED formatting) instead of `PacificTimeUSCanadaTijuana`, a `platform/docs/providers/microsoft.md` (A8-11).
8. Safety: inject `Status: Paused` on generic creates (A8-01); allowlist customer-service paths (A8-03); treat Audience Network campaigns (`CampaignType: Audience`) and Shopping campaigns explicitly instead of assuming Search.
