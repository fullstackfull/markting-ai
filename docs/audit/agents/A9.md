# A9 — Reddit Ads expert

Audit date: 2026-10-02. Repository: `/home/user/markting-ai` at `f80877c`. Reddit provider is the unmodified upstream adport package (`platform/packages/reddit`, imported at adport `bde6fed`, UPSTREAM.md:9; `git log --follow platform/packages/reddit` shows a single import commit `fa7bf19`).

Question answered: can MARKTING-AI *understand and manage Reddit Ads like an expert media buyer*, not merely "is there a connector". Short answer: there is a thin, security-conscious Reddit Ads API v3 pass-through (3 read tools, 6 guarded writes, 8 unit tests, campaign-level normalized report with purchase-only conversions). It is not an expert system for the channel: ad-group budgets (the default Reddit budgeting model) cannot be changed at all, the normalized conversions ignore every non-purchase event, breakdowns/audiences/frequency/pacing/bidding/learning signals are absent or raw pass-through, and the AI engine has no Reddit adapter of its own (fixtures with invented schemas offline, Pipeboard MCP live).

## Findings

### A9-01 — Ad-group (non-CBO) budgets cannot be changed through any tool; the error message points to a tool that does not exist
- Severity: **P2** · Classification: VERIFIED_CODE
- Evidence: `platform/packages/reddit/src/provider.ts:329-331` (`reddit_set_budget` throws `not a CBO campaign; budget its ad groups instead`); `platform/packages/reddit/src/tools.ts:201-293` (the complete tool list: no ad-group budget tool); `provider.ts:372-374` + `provider.ts:453` (`reddit_api_update` rejects any body containing `goal_value|spend_cap|bid_value|budget|daily_budget|lifetime_budget`, "require a typed budget tool"); `platform/apps/cloud/lib/markting/translate.ts:108` (every engine `update_campaign_budget` proposal for Reddit is mapped to `reddit_set_budget`).
- Description: In Reddit Ads the budget normally lives on the ad group (`goal_type`/`goal_value` on `ad_groups/{id}`); CBO (`is_campaign_budget_optimization`) is the newer opt-in. The typed tool only handles CBO campaigns, the generic PATCH tool deliberately blocks money fields, and there is no `reddit_set_ad_group_budget`. Result: for the common Reddit account there is **no path to change a budget** (neither raise nor lower), and the only emergency control is pause. The AI bridge inherits this: a proposal on a non-CBO campaign fails at preview.
- Impact: day-to-day media buying (scale winners, trim losers) is impossible; the operator is told to use a tool that is not there.
- Recommendation: add a typed `reddit_set_ad_group_budget` (GET `ad_groups/{id}`, assert `ad_account_id`, carry `goal_type`, emit `fromMicros/toMicros`), and a typed bid tool (`bid_value` / `bid_strategy`) with the same before/after rails; have the bridge choose by entity type.

### A9-02 — `reddit_api_read` single-resource paths bypass the workspace account scope
- Severity: **P2** · Classification: VERIFIED_CODE
- Evidence: `platform/packages/reddit/src/provider.ts:424-428` (`assertReadScoped` returns for `^(campaigns|ad_groups|ads|structured_posts)/[^/]+$` with no ownership check); contrast `provider.ts:402-407` (`assertOwnedResource`, used only by update/delete) and `provider.ts:394-400` (`getOwnedCampaign`); `platform/apps/cloud/lib/cloud/account-scope.ts:48-54` (cloud authorizer validates only `input.account_id`, not the path); `platform/docs/providers.md:20` claims `reddit_api_read` "covers account-scoped GET".
- Description: A tenant whose workspace has Reddit account A enabled and account B (same OAuth grant / same business) disabled can call `reddit_api_read{account_id: A, path: "campaigns/<B-campaign-id>"}` and receive B's full configuration. The write path proves ownership first; the read path does not. This is not cross-tenant (the OAuth grant bounds it) but it defeats the "enabled accounts" entitlement that `AccountScopedProvider` enforces for every other read.
- Impact: entitlement bypass for configuration reads; audit/account-scope guarantees in `docs/deployment-model.md` are weaker for Reddit than documented.
- Recommendation: for single-resource reads, fetch and compare `ad_account_id` (one extra GET), or restrict reads to `ad_accounts/{account_id}/...` paths only.

### A9-03 — `reddit_set_budget` lets a LIFETIME_SPEND budget be silently re-typed as DAILY_SPEND at the same amount; the delta rails see a 0% change and the preview does not show the type switch
- Severity: **P1** · Classification: VERIFIED_CODE
- Evidence: `platform/packages/reddit/src/provider.ts:333-339` (summary and `changes` print `campaign.goal_type` and old→new `goal_value`, never the requested `payload.budget_type`; `execute` PATCHes `goal_type: payload.budget_type`); `provider.ts:336` (`budgetDeltas` = `fromMicros: campaign.goal_value, toMicros: payload.budget_micros` regardless of type); `platform/packages/core/src/policy/engine.ts:133-153` (rails compare only micros, abs cap is named "daily" but applied to whatever is passed); `platform/apps/cloud/lib/markting/translate.ts:108` (the engine bridge **always** sends `budget_type: 'DAILY_SPEND'`).
- Description: A CBO campaign with `goal_type: LIFETIME_SPEND, goal_value: 3,000,000,000` (3,000 currency units for the whole flight). Call `reddit_set_budget{budget_micros: 3_000_000_000, budget_type: 'DAILY_SPEND'}`. Preview: `~ campaign X LIFETIME_SPEND 3000000000 → 3000000000`, budget delta 0% → passes `max_budget_delta_pct`; passes `max_daily_budget_micros` if unset (default null, `policy.ts:15`). Apply PATCHes `goal_type: DAILY_SPEND` → the campaign now spends the flight budget every day. The approver saw "no change". Because the bridge hard-codes `DAILY_SPEND`, any engine proposal against a lifetime-budgeted Reddit CBO campaign takes this path.
- Impact: 30x-class overspend with an approval that was not informed; the two-step rail exists but its preview is blind to the dangerous field.
- Recommendation: reject `budget_type` changes in `reddit_set_budget` (or require an explicit separate tool), print old→new `goal_type` in `changes` and add a coercion/warning line, and normalize lifetime vs daily before computing the percent delta (e.g., divide lifetime by remaining flight days or refuse to compare).

### A9-04 — Normalized conversions are purchase-only and conversion value assumes cents; zero is reported instead of null
- Severity: **P2** · Classification: VERIFIED_CODE (behaviour) / NOT_VERIFIED (cents unit against Reddit documentation)
- Evidence: `platform/packages/reddit/src/provider.ts:102-109` (fields requested: SPEND, IMPRESSIONS, CLICKS, CONVERSION_PURCHASE_CLICKS, CONVERSION_PURCHASE_VIEWS, CONVERSION_PURCHASE_TOTAL_VALUE); `provider.ts:230-231` (`conversions` = purchase clicks + purchase views; `conversionValue = … / 100`); `provider.ts:232-239` (every ratio defaults to `0`, never `null`/undefined); `platform/packages/core/src/model.ts:44` (`metrics: Partial<Record<MetricName, number>>` permits omission); `test/reddit.test.ts:97,110` (only evidence for the cents assumption is the self-authored fixture); `platform/docs/providers.md:104` (claim "Conversion total-value report fields use cents").
- Description: Reddit reports many conversion events (signup, lead, add-to-cart, page visit, view content, app install, custom) and the ad group's optimization goal determines which one matters. The normalized report hard-codes Purchase. A lead-gen advertiser sees `conversions: 0, cpa: 0, roas: 0` — presented as real numbers (the engine playbook even says "treat gaps as unavailable, not as zero", `engine/workspace/skills/paid-media-wiki/benchmarks.md:24-25`). Click-through and view-through purchases are summed with no attribution note. The `/100` cents divisor could not be checked against Reddit's reference (docs unreachable, see Commands); if the field is micros like every other monetary field in the same response, conversion value and ROAS are overstated 10,000x.
- Impact: wrong efficiency numbers for most Reddit objectives; a reviewer cannot distinguish "no purchases" from "not measured".
- Recommendation: request the conversion fields matching the ad group's `goal`/optimization event (or all `CONVERSION_*` totals) and map to `conversions`; omit `cpa`/`roas` when conversions are 0; verify the value unit against a real account before shipping (README:119 already says "needs a real-account tester").

### A9-05 — `reddit_report` default `fields` are lowercase while the same provider documents and sends uppercase request enums
- Severity: **P3** · Classification: VERIFIED_CODE (inconsistency) / NOT_VERIFIED (whether Reddit rejects lowercase)
- Evidence: `platform/packages/reddit/src/tools.ts:233` (`fields … default(['spend', 'impressions', 'clicks'])`); `provider.ts:52-53` ("Reddit v3 request enums are uppercase even though response object keys are lowercase"); `provider.ts:103-109` (normalized path sends `SPEND`, …). `rawReport` (`provider.ts:123-155`) has no test.
- Impact: the model's most natural call (`reddit_report` without `fields`) probably fails or returns nothing; no test would catch it.
- Recommendation: uppercase the default and `.transform(f => f.map(x => x.toUpperCase()))`; add a wire test for `rawReport`.

### A9-06 — Generic create/update rails misclassify bids and lifetime values as daily budgets, and the money-key regex is name-based
- Severity: **P3** · Classification: VERIFIED_CODE
- Evidence: `provider.ts:453` (`MONEY_KEY` includes `bid_value`); `provider.ts:461-472` (`collectMicros` turns every matching integer into a `budgetDeltas.toMicros`); `engine.ts:137-141` (compared to `max_daily_budget_micros`); `provider.ts:355` (`coerceCreatedStatuses` only for paths ending `campaigns|ad_groups|ads`).
- Description: creating an ad group with `bid_value: 2_500_000` (2.50 CPC) is checked against the *daily budget* cap; a `LIFETIME_SPEND` goal is checked against a daily cap. Conservative (false rejections), not unsafe. Conversely, `reddit_api_update` on an ad group may change `goal_type` alone (DAILY→LIFETIME) because `goal_type` is not a money key — same semantic risk class as A9-03 but on ad groups.
- Recommendation: type the deltas (budget vs bid vs cap, daily vs lifetime) and gate `goal_type`/`bid_strategy` changes explicitly.

## What a world-class system would need (gaps, concrete)
1. Typed ad-group tooling: `reddit_ad_groups` (goal_type/goal_value/bid/optimization goal/targeting summary), `reddit_set_ad_group_budget`, `reddit_set_bid`, `reddit_set_ad_group_status`, all with ownership + before/after rails (closes A9-01, A9-06).
2. Objective-aware conversions: read the ad group's optimization event and request the matching `CONVERSION_*` fields; expose click vs view attribution and `metrics_updated_at` freshness; null, not zero (closes A9-04).
3. Typed breakdowns: DATE/HOUR, COUNTRY/REGION/DMA, COMMUNITY, INTEREST, PLACEMENT (feed vs conversation), DEVICE/OS — with normalized rows, so community-level and placement-level analysis (the core of Reddit buying) is possible without raw JSON.
4. Pacing and flight math: spend-to-date vs `goal_value` (daily and lifetime), end-date awareness, underdelivery detection; lifetime↔daily type changes shown and gated (closes A9-03).
5. Reach/frequency and creative fatigue per community and ad; frequency caps are a real Reddit lever.
6. Account timezone reporting (`time_zone_id` from the ad account) so numbers reconcile with Ads Manager.
7. Rate-limit aware client (429 + `X-Ratelimit-*` backoff), serialized token refresh, structured error parsing.
8. Recorded-fixture contract tests against Reddit (reports pagination, error bodies, enum lists post-migration) and a real-account smoke test before any write is enabled.
9. Engine: a first-party Reddit adapter or a pinned Pipeboard Reddit schema with unit assertions; Reddit-specific skill knowledge (community targeting, promoted-post lifecycle, conversation placement, CPM-first auction, pixel/CAPI setup).
10. Conversion-measurement setup support (pixel health, event coverage) and account-health signals (funding instrument, ad review rejections).
