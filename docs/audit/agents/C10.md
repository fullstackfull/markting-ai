# C10 — AI cost engineer

Audit date: 2026-10-02. Repository: `/home/user/markting-ai` (paths below are relative to it). Nothing outside this file was modified; scratch artefacts live under the session scratchpad (`.../scratchpad/c10/`).

Headline: the engine ships with **zero model cost by default** (`MARKTING_ENGINE_MODE=demo`, scripted model), but the moment `live` is enabled there is **no prompt caching, no context compaction below 850K tokens, no token/cost metering, and no spend quota** anywhere in engine, host or adport. Under the default `anthropic:claude-sonnet-4-6` the realistic cost is roughly **$0.32 for a fresh analysis turn, rising linearly to ~$3.2 by the tenth turn of the same thread**, i.e. **~$18 for a 10-turn conversation**, while the Operator plan sells two seats for EUR 19/month. The deterministic report path costs $0 in model tokens (verified). All dollar figures are estimates built on the measured prompt sizes and the price table in §4, which is an assumption.

### 3.2 Structural cost controls present in code (VERIFIED_CODE)

- Per-run model-call cap: `ModelCallLimitMiddleware(run_limit=settings.paid_media_max_model_calls, exit_behavior="end")`, default 40, floor 5 (`assembly.py:257-259`, `config.py:120`). Counted in `before_model/after_model` hooks (`langchain/agents/middleware/model_call_limit.py:168,236`), so retried attempts are **not** counted.
- Per-call timeout: `ModelTimeoutMiddleware(120 s)` via `asyncio.wait_for` (`middleware/timeout.py:36`), plus SDK `timeout=120, max_retries=2` (`assembly.py:170`).
- Retry: `ModelRetryMiddleware(max_retries=2, on_failure="continue")` (`assembly.py:71,255`); defaults `backoff_factor=2.0, initial_delay=1.0, max_delay=60.0`, retries any exception by default (`langchain/agents/middleware/model_retry.py:119-125`).
- Tool-result offload: results > 6,000 chars become a 400-char preview + artifact stub (`config.py:134`, `offload.py:15,37-53`), bounding per-step context growth to ≈1.5K tokens for provider reads.
- Deferred tool loading for Anthropic/OpenAI (`tool_selection.py:94-118,166-170`); portable LLM selector for other providers with optional separate `PAID_MEDIA_TOOL_SELECTOR_MODEL` (`config.py:116`, `assembly.py:217-229`).
- Context compaction: deepagents `create_summarization_middleware(model, backend)` (`deepagents/graph.py:803`) with `trigger=("fraction", 0.85)`, `keep=("fraction", 0.10)` when the model profile has `max_input_tokens` (`deepagents/middleware/summarization.py:274-286`); `claude-sonnet-4-6` profile `max_input_tokens=1,000,000` (`langchain_anthropic/data/_profiles.py:361`) → compaction only at ≈850K tokens. The summary call uses the **main model** (no cheaper summarizer hook).
- No extended thinking (`thinking=None`, command 9) — no thinking-token spend.

## 5. Findings

### C10-01 — No token or cost accounting anywhere in the stack
- Severity: **GAP** (high business impact once live). Classification: VERIFIED_CODE.
- Evidence: command 4 (exit 1: no `usage_metadata`/`input_tokens`/`cache_control` in `engine/src`); command 5 (no metering in `services/` or adport); `docs/TODO.md:8` lists "whether engine usage (model tokens, report runs) is metered per organization" as an open question; the only observability hook is optional LangSmith tracing (`admin/actions.py:219,905`, `model_presets.py:15`).
- Description: `ChatAnthropic` returns `usage_metadata` on every `AIMessage`, but nothing in the engine, host or adport records it, attributes it to `caller_ref`/organization, or exposes it. Threads are namespaced per org/user (`assistant.ts:35-37`) so attribution would be possible, but no table or log exists.
- Impact: finance cannot see spend per tenant; no basis for quotas, alerts or pricing; the plan economics in §4.6 are invisible to the operator.
- Recommendation (do not implement in this audit): record `usage_metadata` per model call in a middleware (`wrap_model_call`), persist `{org, user, thread, model, input, cached_input, output, cost_estimate}` in Postgres, expose per-org monthly totals to adport billing, and alert at thresholds.

### C10-02 — No spend quota; rate limit of 120 assistant turns/min/user is a throughput limit, not a cost limit
- Severity: **P1** (serious financial risk) **conditional on `MARKTING_ENGINE_MODE=live`**; the shipped default `demo` costs $0 (`.env.example:51`, `docker-compose.yml:51`, `serve_demo.py:133`). Classification: VERIFIED_CODE (mechanics), INFERRED (dollar figures).
- Evidence: `platform/apps/cloud/lib/cloud/repository.ts:355` (`limit = 120, windowSeconds = 60`), `app/api/assistant/messages/route.ts:13`; engine cap is per run only (`config.py:120`, `assembly.py:257-259`); no per-thread, per-caller or per-org budget in `surfaces/api/app.py`, `surfaces/runner.py`, `serve_demo.py`; plan definitions carry no usage dimension (`plans.ts:11-21`: accounts, members, retention, writeAccess only; `plan-limit.ts:1` kinds `active_accounts | members | retention`).
- Impact: a single Free-plan seat can legitimately spend ≈$106/month and can be driven to hundreds of dollars per minute (§4.6). Charges accrue on the operator's single `ANTHROPIC_API_KEY`.
- Recommendation: add a per-organization monthly token/dollar budget enforced in adport before calling the engine (402 `PLAN_LIMIT` already exists as a pattern, `plan-limit.ts:19`), lower the assistant rate limit to something like 10/min and 200/day per user, and add a per-thread lifetime call budget in the engine (a `thread_limit` on `ModelCallLimitMiddleware` is supported by the middleware signature, `model_call_limit.py:129-131`).

### C10-03 — No prompt caching: ~5.6K-token stable prefix and the whole transcript are re-billed at full price on every call
- Severity: **P2** (substantial cost deficiency). Classification: VERIFIED_CODE + VERIFIED_RUNTIME.
- Evidence: command 4 (no `cache_control` in engine); `langchain_anthropic/chat_models.py:1578-1583` applies breakpoints only when a `cache_control` kwarg is passed; §3.1 shows the identical 7,562-char system block and 21,217-char tool block on all 8 calls.
- Description: the prefix is stable and cache-friendly by construction (frozen `instructions.md`, deterministic tool list, date block last — `assembly.py:263`), so the main precondition for caching is already met; the breakpoint is simply never set.
- Impact: §4.3 — caching cuts a fresh turn from $0.32 to ~$0.10 and a 10-turn thread from $17.77 to ~$2.49 (≈85%), with the largest savings exactly where cost grows fastest (long threads).
- Recommendation: pass `cache_control={"type": "ephemeral"}` on the model (top-level auto-caching in `langchain-anthropic`), or set breakpoints on the system prompt/tools and on the last message in a `wrap_model_call` middleware; verify with `usage.cache_read_input_tokens > 0`; keep `CurrentDateMiddleware` as the last system block (daily invalidation only).

### C10-04 — Unbounded context growth: compaction triggers at ~850K tokens, UI reuses one thread per session
- Severity: **P2**. Classification: VERIFIED_CODE (mechanics), INFERRED (cost curve).
- Evidence: `deepagents/middleware/summarization.py:274-286` (`trigger=("fraction", 0.85)`, `keep=("fraction", 0.10)`); `langchain_anthropic/data/_profiles.py:361` (`max_input_tokens: 1000000`); `deepagents/graph.py:803` (summarizer = main model); `assistant-chat.tsx:25,45` (threadId kept for the session); `serve_demo.py:208-221` (Postgres checkpointer when `DATABASE_URL` is set); engine exposes no history-trim or per-thread cap.
- Impact: turn cost grows ≈$0.32 per prior turn on Sonnet 4.6 (§4.3), so the tenth turn costs 10× the first and a 20-turn thread ≈$68. When compaction finally fires it is itself a ~850K-token Sonnet call (≈$2.6) — and it uses the main model, not a cheap one.
- Recommendation: set an explicit `SummarizationMiddleware` with `trigger=("tokens", 60_000)` and `keep=("messages", 10)` or similar, point the summarizer at Haiku 4.5, and/or start a new engine thread per adport conversation after N turns or M minutes idle.

### C10-05 — Client-side timeouts abandon runs that keep spending on the engine
- Severity: **P2** (reliability + cost). Classification: VERIFIED_CODE (timeouts), INFERRED (continuation after disconnect — not exercised at runtime).
- Evidence: adport aborts the fetch at `MARKTING_ENGINE_TIMEOUT_MS` default 240,000 ms (`env.ts:18`, `engine-client.ts:73,82`); Next route `maxDuration = 300` (`route.ts:7`); engine `post_message` simply awaits the run (`surfaces/api/app.py:92`), with no cancellation on client disconnect and no run-level deadline; a single logical model call may take up to 3 × 120 s + backoff (§3.2); a run may make 40 calls.
- Impact: a slow live turn is billed in full although the user sees "The analysis engine is not reachable right now." (`assistant.ts:46`), and the user's natural retry starts a second concurrent run on the same thread (double spend, interleaved checkpoints).
- Recommendation: add a run-level wall-clock budget in the engine (e.g. 180 s) that ends the run with a message, align it with `MARKTING_ENGINE_TIMEOUT_MS`, return a 202 + poll or stream events for long runs, and dedupe concurrent runs per thread.

### C10-06 — Retry amplification is uncounted and can bill partial generations
- Severity: **P3**. Classification: VERIFIED_CODE (mechanics), INFERRED (billing of timed-out generations).
- Evidence: SDK `max_retries=2` (`assembly.py:170`) nested inside `ModelRetryMiddleware(max_retries=2)` (`assembly.py:71,255`) → up to 9 HTTP attempts per logical call; `ModelTimeoutMiddleware` cancels at 120 s (`timeout.py:36`) and the resulting `TimeoutError` is retried by the default `retry_on` (`model_retry.py:120`); the call cap counts in `before_model/after_model` (`model_call_limit.py:168,236`), so retries are not counted.
- Impact: a stalled provider can turn one logical call into ~6 min of wall clock and up to three billed server-side generations; the 40-call cap does not bound this.
- Recommendation: retry only on transient classes (429/5xx/connection), not on the local timeout; count attempts against the run budget; prefer streaming so the 120 s guard sees progress rather than silence.

### C10-07 — `max_tokens` is left at the profile default of 128,000
- Severity: **P3**. Classification: VERIFIED_CODE / VERIFIED_RUNTIME (command 9).
- Evidence: engine passes no `max_tokens` (`assembly.py:170-174`); `langchain_anthropic/chat_models.py:1390-1397` fills it from the profile; `_profiles.py:362` `max_output_tokens: 128000`.
- Impact: the only practical ceiling on output per call is the 120 s timeout (≈10K tokens ≈ $0.15 on Sonnet 4.6, INFERRED from typical throughput); a chat agent that is told to keep tables in files (`instructions.md:52-54`) never needs 128K.
- Recommendation: set `max_tokens` ≈ 4,096–8,192 for chat turns via `resolve_model` kwargs.

### C10-08 — Cheaper-model routing exists only for the portable selector path and is unused with the default provider
- Severity: **P3 / GAP**. Classification: VERIFIED_CODE.
- Evidence: `PAID_MEDIA_TOOL_SELECTOR_MODEL` (`config.py:116`) is consulted only when `SelectionStrategy.PORTABLE_SELECTOR` applies (`assembly.py:217-229`, `tool_selection.py:159-176`); the Anthropic default uses provider-native search (`tool_selection.py:115-118`) so the selector model is never built; the summarizer is hard-wired to the main model (`deepagents/graph.py:803`); the setup console's recommended preset is the LangSmith gateway with Sonnet 4.6 (`model_presets.py:11-20`), which also disables native tool search (`tool_selection.py:97-100`, `_GATEWAY.native_tool_search=False`) and therefore adds a selector LLM call per step on the main model unless a cheaper selector is configured.
- Recommendation: document and default `PAID_MEDIA_TOOL_SELECTOR_MODEL=anthropic:claude-haiku-4-5-20251001` whenever the portable path is active; add a configurable summarizer model.

### C10-09 — Local demo/test suite is coupled to host runtime state (observation, not a cost defect)
- Severity: **P3**. Classification: VERIFIED_TEST (commands 6, 7).
- Evidence: `paid-media-agent demo --with-proposal` and `tests/behavior/test_scripted_behavior.py` fail in this checkout with `kill_switch: .../engine/workspace/KILL_SWITCH exists`; the file is untracked and written by `serve_demo.engage_kill_switch` (`serve_demo.py:173-180`).

## 7. What a world-class system would need (concrete gaps)

1. **Metering**: a `UsageMiddleware` capturing `usage_metadata` per call → `pma_model_usage(org, user, thread, model, in, cached_in, out, est_cost, ts)`; nightly roll-ups surfaced in adport Billing; alerts at 50/80/100% of plan budget.
2. **Budgets as plan dimensions**: `maxMonthlyModelTokens` (or dollars) on `PlanDefinition`, enforced in `runAssistantTurn` before the engine call with the existing 402 `PLAN_LIMIT` contract; per-thread lifetime call cap (`thread_limit`) in the engine; a hard org kill switch for runaway spend.
3. **Prompt caching by default**: ephemeral breakpoints on system+tools and on the last message; measure `cache_read_input_tokens`; keep the date block last; aim for ≥70% cached input on turn ≥2.
4. **Context policy**: compaction at ~60K tokens with Haiku 4.5 as summarizer; new engine thread per adport conversation after N turns/idle; strip offload previews from history after they are superseded.
5. **Model tiering**: Sonnet 5.5 (or the cheapest Sonnet that passes the behaviour tests) for chat; Haiku 4.5 for selector/summarizer/classification of "is this a report request" so deterministic paths can be invoked without the agent loop; Opus only on explicit operator opt-in.
6. **Offload more to code**: route "weekly/monthly report" intents straight to `run_cadence_report` (already $0) instead of the agent; pre-compute `compare_periods` for connected accounts nightly so the agent reads one artifact instead of N provider reads.
7. **Run lifecycle**: engine run deadline aligned with `MARKTING_ENGINE_TIMEOUT_MS`, cancellation on client disconnect, per-thread run dedupe, async job + poll/stream for long turns.
8. **Token hygiene**: `max_tokens` 4–8K for chat; trim tool descriptions (the six filesystem tool schemas alone are 7.9K chars, `tools_captured.json`); keep the skills listing but shorten the deepagents boilerplate if the framework allows.
9. **Evaluation of cost per completed task**: a small eval over the scripted questions measuring tokens-per-reconciled-answer, re-run on every model/prompt change (the behaviour tests already assert correctness; add a token budget assertion).
