## Findings

### A11-01 — `apple_upload_asset` is an arbitrary server-file read + SHA-256 oracle in the multi-tenant cloud runtime
- Severity: **P1** (security; information disclosure, file-existence oracle, memory DoS on a shared server). Not P0 because exfiltration of file *content* is bounded: upload proceeds only for `.png/.jpg/.jpeg/.heic` extensions.
- Classification: VERIFIED_CODE
- Evidence: `platform/packages/apple/src/provider.ts:547` (`const file = await readFile(payload.file_path);`) runs inside `plan()`, which `previewWrite` calls (`provider.ts:228-235`) — i.e. before any pending-operation approval. `provider.ts:552` throws `AdportError('INVALID_INPUT', "... expected ${expected}, got ${actualSha256}")`, revealing the real hash of whatever path was supplied; the extension check `assetContentType` runs only afterwards (`provider.ts:555`). `platform/packages/mcp/src/index.ts:186-188` returns `err.toJSON()` (code + message) verbatim to the MCP client for every `AdportError`; non-Adport errors (e.g. ENOENT) get the generic INTERNAL message (`index.ts:189-193`), creating an existence oracle. `platform/apps/cloud/lib/cloud/runtime.ts:115-117` registers *all* `appleTools(provider)` for cloud tenants with no filtering of `apple_upload_asset`; `rg -n "upload_asset|file_path" platform/apps/cloud` → no matches (no cloud-side restriction). `rg -n "readFile\(" platform/packages/*/src/provider.ts` → Apple is the only provider reading local files.
- Description: The tool was designed for the local CLI ("binds the exact local file contents", `tools.ts:150`). In the hosted runtime the "local file" is the server's filesystem. Any tenant with `tools:write` + write entitlement + an enabled Apple account can (a) learn whether any server path exists, (b) obtain the SHA-256 of any server-readable file (e.g. `/proc/self/environ`, `.env`, deployed source) in the preview step, and (c) if a secret-bearing file happens to carry an image extension, push its bytes to Apple's asset store under their own brand. Reading `/dev/zero`-like paths or huge files is also an unbounded memory read.
- Impact: Cross-tenant/host confidentiality leak and DoS surface in `apps/cloud`.
- Recommendation: In cloud mode, remove `apple_upload_asset` from the registered tool list or replace `file_path` with an upload handle (tenant-scoped object storage). Never echo computed hashes of unmatched files. Enforce extension/size checks before reading.

### A11-02 — Cloud "service-provider" OAuth flow is undocumented in Apple's public Platform API docs and the connector cannot persist a rotated refresh token
- Severity: **P1** (production blocker for the only Apple path cloud tenants have)
- Classification: NOT_VERIFIED (flow) / VERIFIED_CODE (no rotation persistence)
- Evidence: `platform/apps/cloud/lib/cloud/provider-oauth.ts:203-205` (`APPLE_AUTHORIZE = https://appleid.apple.com/auth/oauth2/v2/authorize`, `APPLE_SCOPE = 'searchads'`), `:240-256` (authorization_code exchange expects `refresh_token`), `:258-259` (`revoke()` returns false). Apple's public OAuth page for the Platform API (fetched) documents only `client_credentials` + `searchadsorg`; the web search found only that third-party providers must "contact ads-registration@group.apple.com" and that advertisers grant access through a "Sign in with Apple" button inside the partner's platform — the authorize URL, scope string and refresh semantics are not publicly specified. `platform/packages/apple/src/client.ts:122-128` uses `grant_type=refresh_token`; `client.ts:148-149` parses only `access_token`/`expires_in` and discards any `refresh_token` in the response; `AppleAdsClient` has no `onRefreshToken` callback, unlike Microsoft/Reddit (`runtime.ts:120-124, 129-136`). `rotateProviderTokens` exists (`credential-rotation.ts:15`) but is never wired for Apple.
- Description: The cloud path depends on an Apple partner registration that the repo cannot prove exists (the `.env.example:69-71` comment calls it "Apple-approved service-provider registration"; nothing in the repo evidences approval). If Apple rotates or expires refresh tokens, every Apple cloud connection silently dies and the user must reconnect; there is no revocation at disconnect.
- Impact: MARKTING-AI cloud tenants may be unable to connect Apple Ads at all; if they can, token lifecycle is fragile.
- Recommendation: Obtain and document the partner registration and the exact OAuth contract from Apple; add refresh-token rotation persistence like Microsoft/Reddit; add a connection-health probe (`GET /v1/me`).

### A11-03 — Normalized report sends `conversion_value: 0` and `roas: 0` as real numbers, so Apple ROAS reads as 0 instead of "unavailable"
- Severity: **P2**
- Classification: VERIFIED_CODE
- Evidence: `platform/packages/apple/src/provider.ts:206` (`conversion_value: 0`), `:211` (`roas: 0`), with the comment at `:198` "No revenue metric exists." `platform/packages/core/src/report-summary.ts:4` treats any finite number as *available*; `:27-31,37-38` then computes group ROAS as `0 / spend = 0` with `roas_method: 'conversion_value_over_spend'`. `platform/packages/core/src/tools/builtin.ts:57` tells the model "Null metrics are unavailable" — Apple never returns null. Apple's `AppsMetrics` (fetched) indeed has no revenue field.
- Description: An expert needs "ROAS not measurable on Apple Ads (no in-platform revenue); use installs/CPI/CPA" — the system instead reports ROAS = 0, which the engine/LLM will read as catastrophic performance. Peer rows with a shared currency label would also absorb the zeros; Apple rows have no currency (see A11-04) so today they only pollute their own group.
- Recommendation: Omit `conversion_value`/`roas` (or set `null`) for Apple and surface "not available on this channel".

### A11-04 — Account currency and account health are never fetched; report rows carry no currency; `status` is overloaded with the user's roles
- Severity: **P2**
- Classification: VERIFIED_CODE (+ Apple docs)
- Evidence: `provider.ts:110-120` builds accounts from `GET acls` with `status: acl.roles?.join(',')` (`:118`) and no `currency`. Apple's `AclAdAccount` has only `id,name,orgId` (fetched `useracl.json`), while `AdAccount` (`GET /v1/ad-accounts/{id}`) exposes `currency`, `timezone`, `paymentModel`, `systemStatus`, `systemStatusReasons` (fetched `adaccount.json`) — the provider never calls it. `toReportRow` (`provider.ts:216-225`) sets no `currency` even though `localSpend.currency` is on every row; `BudgetDelta.currency` (`core/src/provider.ts:27`) is never populated by any Apple plan (`:313-316, 383-386, 458-463, 695-699, 733-737`). Cloud persists `account.currency ?? null` (`account-selection.ts:139`) → Apple accounts stored with null currency; `builtin.ts:118-129` then cannot label Apple rows.
- Description: Cross-channel summaries fall back to per-account grouping (safe) but the operator never sees the currency of Apple spend; the policy caps (`max_daily_budget_micros`) are compared currency-blind; account suspension reasons (`ORG_NO_PAYMENT_METHOD_ON_FILE`, `LOC_EXHAUSTED`, …) are invisible; the `status` column shows "ADMIN" rather than an account status.
- Recommendation: Enrich `listAccounts` with `GET ad-accounts/{id}`; propagate `localSpend.currency` to rows and `BudgetDelta.currency`; expose `systemStatusReasons` as health signals.

### A11-05 — Normalized `report()` request shape is only partly backed by Apple's documentation; two doc pages say a `campaignId` filter is mandatory and the provider sends none
- Severity: **P2** (if Apple enforces it, every normalized Apple report and the cloud dashboard fail with 400)
- Classification: INFERRED (docs are internally inconsistent; not runtime-verified)
- Evidence: `provider.ts:173-179` body = `pagination`, `sorting:[{field:'id'}]`, `timeRange{…,timeZone:'UTC'}`, `options.includeRows:['GRAND_TOTAL']` — no `filters`. Fetched `get-app-campaign-reports.json`: "filters (array, required) — Must include campaignId filter"; fetched `appsreportingrequest.json`: "`campaignId` is a required filter for every apps report request"; but fetched `reports.json` and `filter.json` describe filters as optional. `options.includeRows` values `GRAND_TOTAL|EMPTY_METRICS` (fetched `appsoptions.json`) and `pageSize` max 5000 (`reports.json`) match the code (`provider.ts:175,178`). Response parsing expects `rows[].totalMetrics/metadata` (`provider.ts:54-57`), consistent with the documented response.
- Description: The README claims Apple was "exercised against a live account" (`platform/README.md:117`) but the vendored commit history is a single import (`git log`), the test suite uses only hand-written fixtures (`apple.test.ts:138-180`), and the v1 report body cannot be confirmed from the repo. Also `sorting.field:'id'` is not confirmed as a valid report sort field.
- Recommendation: Run one live `reports/apps/campaigns/query` smoke test; if `campaignId` is required, list campaigns first and filter with `IN`.

### A11-06 — Normalized metrics are narrow and partly re-derived: only campaign/account levels, totals only, no breakdowns, view-through installs counted as "conversions"
- Severity: **P2** (functional deficiency for an expert workflow)
- Classification: VERIFIED_CODE
- Evidence: `provider.ts:162-164` rejects `ad_group`/`ad` levels ("report supports campaign and account levels in v0") whereas Google, Meta, TikTok, Reddit, Snapchat providers map all four levels (`rg` results: e.g. `platform/packages/google/src/provider.ts:22,143`, `platform/packages/snapchat/src/provider.ts:15`). `provider.ts:197-212`: `clicks=taps`, `conversions=totalInstalls` (Apple: "Total installs combining tap and view attribution"), `cpc`/`cpm`/`cpa` recomputed client-side instead of using Apple's `cpt`, `cpm`, `tapInstallCPI`, `totalAvgCPI`. No `granularity`, `groupBy` (`deviceClass, ageRange, gender, countryOrRegion, adminArea, locality` per fetched docs), keyword or search-term reports in the normalized path. Only the App Store reporting family is used; `reports/business-brands/*` (Apple Maps) is reachable solely through raw `apiRead`. `listCampaigns` (`provider.ts:122-128`) fetches one page and never sets `truncated`.
- Recommendation: Add ad-group/keyword/search-term levels, granularity and groupBy pass-through, tap-vs-view install split, pre-orders, and `truncated` handling.

### A11-07 — `apple_set_budget` defaults the currency to `USD` when the campaign has no `dailyBudget.value`
- Severity: **P2** (financial-correctness risk; preview does disclose it)
- Classification: VERIFIED_CODE
- Evidence: `provider.ts:451` (`const currency = current.dailyBudget?.value?.currency ?? 'USD';`) then PUTs `dailyBudget.value` in that currency (`:467-470`). Apple's Campaign `dailyBudget` is `{value | sharedBudgetId}` (fetched `campaigns-data-objects.json`); a campaign on a shared budget has no `value`.
- Description: On a non-USD account with a shared-budget campaign the tool proposes "(unset) → X USD" and attempts to convert a shared-budget campaign into an individually-budgeted one in a foreign currency. Apple will most likely reject the currency mismatch, but on USD accounts the silent shared→individual conversion succeeds.
- Recommendation: Resolve currency from the ad account; refuse when the campaign uses `sharedBudgetId` and point to `apple_set_shared_budget`.

### A11-08 — No 429 / `Retry-After` / rate-limit header handling in the client
- Severity: **P2** (reliability under day-to-day polling)
- Classification: VERIFIED_CODE
- Evidence: `rg -n -i "retry|429|RateLimit|Retry-After" platform/packages/apple/src/` → no matches; `client.ts:154-178` performs a single fetch and throws on any non-2xx. Apple's rate-limits page (fetched) specifies `RateLimit-Limit/Remaining/Reset`, HTTP 429 with `Retry-After`, and exponential backoff.
- Recommendation: Honor `Retry-After`/`RateLimit-Reset` with bounded backoff; surface remaining quota.

### A11-09 — Access token is re-minted on every cloud request; JWT lifetime fixed at 1 h
- Severity: **P3**
- Classification: VERIFIED_CODE
- Evidence: `client.ts:109,117-119` caches the token on the client instance; `runtime.ts:116` constructs a fresh `AppleAdsClient` inside `createTenantRuntime`, which is invoked per HTTP request (`reads.ts:36,52`, `app/mcp/route.ts:14`). `jwt.ts:65` lifetime defaults to 3600 s (allowed up to 180 d).
- Impact: Every tool call pays an extra Apple token round-trip; token endpoint throttling risk.
- Recommendation: Cache tokens per organization (encrypted) with expiry.

### A11-10 — Float money is stringified without rounding; micros computed without `Math.round` in typed tools
- Severity: **P3**
- Classification: VERIFIED_CODE / VERIFIED_RUNTIME
- Evidence: `provider.ts:299` (`amount: String(payload.daily_budget)`), `:374`, `:430`, `:468`; `:321,383,436,458-462` multiply by `UNITS_TO_MICROS` without rounding (vs `Math.round` used in `collectCreatedMoney` `:817,826`). `node -e` run shows `String(0.1+0.2)` → `0.30000000000000004`.
- Recommendation: Normalize to 2-decimal strings and integer micros.

### A11-11 — Typed creation tools hardcode a single buying configuration (search results, TAPS, MANUAL_CPT, CPT, BROAD/EXACT)
- Severity: GAP (documented as such in tool descriptions, so not a defect)

### A11-12 — Generic update money-guard is regex/shape based and bypassable with non-Money scalars
- Severity: **P3** (Apple would reject malformed scalars, so no real money moves)
- Classification: VERIFIED_CODE
- Evidence: `provider.ts:791-793` key regex `/(budget|bidAmount|cpaGoal)/i`; `:800-804` shape check requires `{amount}`. A body such as `{ bid: "5.00" }` or `{ targetCPA: 5 }` passes `containsMoneyField` and reaches `PUT` without a policy delta.
- Recommendation: Deny-list by documented field names per path (`bid`, `bidStrategy`, `dailyBudget`, `targetCPA`, `value`).

## What a world-class system would need (gaps, concrete)

1. **Channel knowledge for the model**: an Apple Ads skill/prompt that explains taps ≠ clicks, tap vs view-through installs, re-downloads, no revenue/ROAS, Search Match, keyword match types incl. PHRASE/CATEGORY, placements (search results, Search tab, Today tab, product pages, Apple Maps), CPT vs CPA/CPM pricing, MAX_CONVERSIONS and target-CPA recommendations, and Apple's ORTZ reporting default.
2. **Normalized reads at all levels**: ad group, keyword, search term, ad; `granularity` (daily/hourly/weekly/monthly with Apple's span limits), `groupBy` dimensions, currency on every row, `truncated` flag, campaign-id filter if required.
3. **Day-to-day optimization loops**: search-term → negative keyword harvesting (bulk negative-keyword create exists raw, no analysis), keyword bid management vs CPA/CPI targets, budget pacing vs `dailyBudget`, impression-share insights (`insights/apps/impression-share` is allowlisted but unused), keyword/phrase suggestions (`suggestions/*` allowlisted but unused), rejection-reason monitoring for creatives.
4. **Account & delivery health**: `AdAccount.systemStatusReasons`, campaign/ad-group `systemStatus*`, budget-order balance (LOC accounts), token/connection health probes.
5. **Safer writes**: resolve currency from the ad account; refuse budget edits on shared-budget campaigns; typed target-CPA tool; keyword/ad-group status tools with wire tests; re-check budget policy at apply.
6. **Hosted-runtime hardening**: remove or re-design `apple_upload_asset` (A11-01); refresh-token rotation persistence and revocation (A11-02); per-org token cache; 429 backoff.
7. **Engine integration**: add `apple_ads` to the engine `Platform` enum, a fixture dataset, spend normalization (`localSpend.amount` whole units), and a bridge mapping to `apple_set_budget`/`apple_set_campaign_status`.
8. **Live contract tests**: a sandbox-free smoke test harness against a real account to confirm report body acceptance (A11-05).
