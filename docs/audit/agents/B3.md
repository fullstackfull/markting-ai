## Findings

### B3-01 — No statistical significance / sample-size engine exists; recommendations rest on raw deltas only
- Severity: P2
- Classification: VERIFIED_CODE
- Evidence: `engine/src/paid_media_agent/tools/compute.py:98-114` (`deltas` computes only absolute and `absolute/prev` relative change), `:375-423` (`summarize` emits those deltas as the analysis output); dependency scan `grep -iE "scipy|statsmodels|numpy|pandas|sklearn" engine/pyproject.toml engine/uv.lock` → no matches.
- Description: The only "analysis" the system computes is arithmetic deltas and ratios. There is no variance, standard error, confidence interval, significance test, or minimum-detectable-effect calculation anywhere in the codebase, and no statistics library is even a dependency. `compare_periods` returns relative percentages (e.g. `spend_change`, CPA % change) with no indication of whether a move is distinguishable from noise.
- Impact: Every recommendation the agent makes about "what changed / what needs attention" is built on point estimates with no uncertainty quantification. Large relative swings on tiny bases look identical to real trends in the tool output; the model must supply all statistical judgment from prose.
- Recommendation: Treat statistics as a GAP to close, not a silent omission. At minimum attach sample-size context (conversions, clicks) to every delta and compute a crude significance/CI band for rate metrics (CVR, CPA, ROAS) so the output itself signals when a difference is within noise.

### B3-02 — `summarize_window` flags day-over-day moves on relative change only, ignoring base size (fires on 2→3 conversions)
- Severity: P2
- Classification: VERIFIED_RUNTIME
- Evidence: `engine/src/paid_media_agent/tools/summary.py:27-28` (`DAY_CHANGE_FLAG = Decimal("0.5")`), `:118-125` (flag when `abs(change) >= DAY_CHANGE_FLAG`, computed as `(cur-prev)/prev`); runtime: `summarize_rows` on daily conversions 2→3→4 returns `flagged_days: ['2026-08-02']` with `flags=['conversions_moved_up']` for the 2→3 day.
- Description: The day-anomaly flag is a pure relative-change threshold with no floor on the absolute base. A 2→3 conversion day (statistical noise) is flagged identically to a material move. The skill `anomaly-and-significance.md:33` explicitly warns "A move from 2 conversions to 4 is not a trend," but the tool emits the flag anyway and relies entirely on the LLM to discard it in prose.
- Impact: The structured signal the model consumes is polluted with small-base noise flags. A model that trusts `flagged_days`/`flags` (or a downstream deterministic consumer) will treat noise as anomalies and can escalate to a recommendation.
- Recommendation: Gate the flag on an absolute floor (e.g. suppress conversion flags below a minimum base) or carry the base alongside the flag so consumers can weight it.

### B3-03 — `propose_change` accepts a recommendation with no evidence linkage and an empty measurement plan
- Severity: P2
- Classification: VERIFIED_CODE
- Evidence: `engine/src/paid_media_agent/tools/write_tools.py:30-43` (`ProposeChangeArgs`: `reason` required free text, `measurement_plan`/`reversal_plan` default `""`), `engine/src/paid_media_agent/tools/writes.py:389-450` (`ProposalService.propose` reads only current provider state for before-values; never references an analysis artifact, conversion count, or data window); `engine/src/paid_media_agent/domain/proposals.py:105` (`measurement_plan: str = ""`); `rg "measurement_plan" engine/src | grep -v test` shows passthrough with no validation.
- Description: A proposal carries no link to the data that justified it — no analysis artifact id, no sample size, no comparison window. `reason`, `measurement_plan`, and `reversal_plan` are free-text strings the model writes, and both plans default to empty and are never validated for presence or content (even for budget/status-flip changes). Nothing in the proposal pipeline can tell whether a change is backed by sufficient data.
- Impact: The AI can stage (and, after one human approval, execute) a budget or status change that is justified by a single noisy day or a thin two-week comparison, with a blank measurement plan, and the system will not object. Data-sufficiency is left entirely to LLM discretion and reviewer attention.
- Recommendation: Require proposals to cite the analysis artifact id they rest on, require a non-empty measurement plan for budget/status-flip operations, and surface the underlying sample size (conversions in the window) on the approval card.

### B3-04 — `classify_risk` is blind to data basis; "risk" is operational only, never statistical
- Severity: P3
- Classification: VERIFIED_CODE
- Evidence: `engine/src/paid_media_agent/tools/writes.py:77-125` — flags are derived solely from the operation name, schema, and before/after values (`status_flip`, `budget_delta`, `destructive_change`, `policy_high_risk`, …); no parameter carries performance data, conversions, or sample size.
- Description: The risk surface shown to the reviewer describes what the mutation does, not whether the decision is statistically justified. A budget cut driven by 36 conversions over two weeks and one driven by 3,600 produce identical risk flags.
- Impact: The human approval gate cannot distinguish a well-evidenced change from an under-powered one, because the only "confidence" signal is whatever prose the model chose to write in `reason`.
- Recommendation: Add a data-basis dimension to the reviewer card (window length, conversions observed, whether the move exceeds normal variation) sourced from the cited analysis artifact.

### B3-05 — Statistical discipline exists only as prose guidance the model may ignore
- Severity: P3
- Classification: DOCUMENTED_ONLY
- Evidence: `engine/workspace/skills/paid-media-wiki/anomaly-and-significance.md:21-40` ("Deterministic tools ... do not run significance tests. Be explicit ... Call a change a trend only when it persists across several days or two full windows"); `engine/instructions.md:16-17` ("Explain ... confidence, and how to reverse it"); `engine/workspace/skills/paid-media-wiki/metrics-and-attribution.md:39-43` ("The agent may recommend a holdout, geo test, conversion lift study, or other experiment").
- Description: The only "sample-size awareness" in the system is written instruction to the LLM. It is sound advice, but it is unenforced: no tool refuses, caveats, or gates on it, and no eval tests it (`grep -i "sample|signif|confidence" engine/tests/eval/questions.json` → 0). Experiments (holdout/geo/lift) are things the agent is told it *may recommend in prose* — none are implemented as a capability.
- Impact: Whether a confident recommendation is made on insufficient data depends entirely on the model obeying guidance at inference time. There is no deterministic backstop and no regression test guarding the behavior.
- Recommendation: Add at least one eval that presents a thin/noisy window and asserts the agent withholds or heavily caveats a recommendation; back the prose with a deterministic small-base caveat in the tool output.

### B3-06 — Demo proposal path hard-codes a budget-cut recommendation with no sample-size check (fixture, reachable pattern)
- Severity: GAP
- Classification: VERIFIED_CODE
- Evidence: `engine/src/paid_media_agent/testing/demo_script.py:158-170` (`_propose` returns a fixed `propose_change` call: reduce `daily_budget` to 240 on `g-103`, reason "Performance Max spend fell while CPA rose", `measurement_plan` "Compare CPA and conversions after 7 complete days"); fixture check on `engine/src/paid_media_agent/fixtures/data/google_ads.json` → g-103 current-14d conversions ≈ 36.3 at ~2–4/day, prior-14d ≈ 67.3; CPA 58.82 → 73.01.
- Description: The scripted demo (no model API) emits a canned budget-cut proposal that is never derived from the analysis artifact it just produced; the decision is hardcoded. It is a legitimate deterministic demo, not a production code path (gated by `scripted:demo` model and `with_proposal`). But it encodes the intended product behavior: produce and execute a budget change from a two-week comparison of a campaign averaging ~3 conversions/day, with no significance/variance step and only a 7-day (~21-conversion) measurement plan.
- Impact: Not a production defect by itself (it is a test fixture), and the demo cannot reach a real ad platform. It is included because it is the clearest illustration of the end-to-end "recommend → propose → execute" pattern operating with zero sample-size awareness; in production the same tools run with an LLM filling in the same free-text fields.
- Recommendation: Keep as a demo, but do not let it stand in for evidence that recommendations are statistically grounded. Pair it with a demo/eval that shows the agent declining on insufficient data.

## What a world-class system would need (gaps, concrete)
- Uncertainty on every rate metric: attach conversions/clicks as the base and compute a CI or at least a Wilson/Poisson band on CVR, CPA, ROAS deltas inside `compute.py`, so the tool output itself distinguishes signal from noise.
- A deterministic data-sufficiency gate on `propose_change` for budget/status operations: minimum observed conversions and window length, with the proposal required to cite the analysis artifact it rests on.
- An absolute-base floor on `summarize_window` day flags so small-number swings do not surface as anomalies.
- Real experimentation primitives (holdout assignment, geo split, lift read-out) rather than prose suggestions, since the product positions itself as an autonomous media buyer.
- Evals that assert restraint on thin data (present ~2–4 conversions/day for two weeks and require the agent to withhold or caveat, not recommend).

## Disagreements / claims in docs that the code contradicts
- `anomaly-and-significance.md:21-24` frames the lack of a significance engine as a deliberate "be explicit" discipline. The code does not merely lack significance tests — it actively emits small-base noise as flags (`summary.py` VERIFIED_RUNTIME: 2→3 conversions → `conversions_moved_up`), so the structured output pushes toward over-reaction, contradicting the doc's cautious spirit.
- `instructions.md:16-17` lists "confidence" as something the agent explains, implying a confidence concept exists. In code there is no confidence computation of any kind; it is a free-text prose field only.
- The product's "AI media buyer" framing implies grounded, data-driven decisions. The propose/execute pipeline (`writes.py:389-450`, `write_tools.py:30-43`) carries no evidence linkage and no data-sufficiency check, so a recommendation on insufficient data is fully reachable and constrained only by unenforced prose.
