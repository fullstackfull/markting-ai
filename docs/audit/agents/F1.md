## Findings

### F1-01 — Vendored engine test suite is red in this checkout because the markting host writes a kill switch into the engine's working directory
- **Severity:** P2 · **Classification:** VERIFIED_TEST / VERIFIED_CODE
- **Evidence:** command 7 (`uv run --frozen pytest -q` → exit 1, 19 failed); failure reason in every case `kill_switch: /home/user/markting-ai/engine/workspace/KILL_SWITCH exists; remove it after the incident review` (scratch log `engine-pytest.log`); `engine/workspace/KILL_SWITCH` present, untracked, gitignored (`engine/.gitignore` line `workspace/KILL_SWITCH`), content "engaged by markting-ai engine host: writes belong to adport" — written by `services/engine-demo/serve_demo.py:173-180` (`engage_kill_switch`, relative path resolved against `root = project_root()` i.e. `engine/`, `serve_demo.py:381,389`); the engine resolves a relative kill-switch path against `skills_root or Path.cwd()` (`engine/src/paid_media_agent/runtime/profiles.py:58-60`, default `Path("workspace/KILL_SWITCH")` at `engine/src/paid_media_agent/config.py:158`); the test `settings` fixture never overrides `paid_media_kill_switch_path` (`engine/tests/conftest.py:36-44`). Command 8 confirms: with the path overridden, 176 pass and the only failure is the test that intentionally exercises the real path.
- **Description:** Running the markting engine host from source once (as Phase 1 did, PHASE1-REPORT.md:36 "run from source") leaves `engine/workspace/KILL_SWITCH` behind, and from then on the engine's own write-gate, approval-claim, replay, concurrency, timeout and recovery contract tests (the safety-critical ones) fail. The compose stack is unaffected (the engine container uses a named volume, `docker-compose.yml:54`), but any developer or auditor running `uv run pytest` in `engine/` after the host sees 19 red tests and cannot distinguish a real upstream regression from this side effect. `make test` does not run the engine suite, so the repo's own test entrypoint never reveals it.
- **Impact:** The upstream safety-net suite is effectively unrunnable in a developer checkout after the demo host has been started from source; documentation (PHASE0-REPORT.md:51 "177 passed") no longer reflects the tree's state. This is a reliability deficiency of the verification process, not a production code path.
- **Recommendation:** Have the host default `PAID_MEDIA_KILL_SWITCH_PATH` to a path inside the configured `paid_media_workspace_root` (the compose stack already isolates that) or to an absolute path outside `engine/`; document `rm engine/workspace/KILL_SWITCH` or add a `make engine-test` target that sets `PAID_MEDIA_KILL_SWITCH_PATH` to a temp path; upstream, propose that `conftest.py`'s `settings` fixture pin `paid_media_kill_switch_path` under `tmp_path` so the suite is hermetic.
