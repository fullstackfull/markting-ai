## Findings

### D0-01 — The engine never analyses connected accounts: the host pins fixture data in both demo and live mode
- Severity: **P1** (README claims the capability; it is the product's core value). Capability: **MOCK_ONLY**.
- Classification: VERIFIED_CODE.
- Evidence: `services/engine-demo/serve_demo.py:163-166` (`assert_fail_closed` refuses to start unless `paid_media_data_mode == "sample"`), `:383-387` (live mode: `base.model_copy(update={"paid_media_data_mode": "sample"})`), `:142-152` (any Pipeboard/X/OpenAI credential refuses boot). `engine/src/paid_media_agent/runtime/catalog.py:51-58` (`sample` → `build_fixture_catalog()`, `read_provider=None`), `runtime/mda.py:57-73` (fixture profile, `FixtureReadProvider`). Docs: `README.md` "Analyses connected accounts (spend, conversions, CPA, ROAS)" / "يحلّل أداء الحسابات المرتبطة"; env table says `MARKTING_DEMO_MODE=false` = "real accounts connected through OAuth" and `MARKTING_ENGINE_MODE=live` = real model.
- Description: In this stack the engine's read path is always the three synthetic datasets (`engine/src/paid_media_agent/fixtures/data/{google_ads,meta_ads,reddit_ads}.json`, aliases `demo-google/meta/reddit` from `engine/config/accounts.example.toml`). `MARKTING_ENGINE_MODE=live` only swaps the scripted model for a real LLM over the same fixtures; `MARKTING_DEMO_MODE=false` only changes which adport runtime previews a proposal. The `markting_account_aliases` table lets an operator bind `demo-google` to a *real* adport account (`lib/markting/repository.ts:40-50`, `translate.ts:133-142`), so a proposal derived from synthetic data could become a real-account preview. The policy engine and a human approver still gate it, but the analysis behind the recommendation would be fiction.
- Impact: the "AI media buyer" cannot see real spend; any live-mode recommendation is not based on the tenant's data. This is also UNSAFE_TO_AUTOMATE as currently wired.
- Recommendation: either (a) feed the engine real reads through adport's normalized `report` tool (an adport-backed `ReadProvider` injected in `build_runtime`), keeping writes proposal-only, or (b) make the README state plainly that the engine is fixture-only until that exists, and refuse non-sandbox alias bindings while `paid_media_data_mode == "sample"`.

## What a world-class system would need (gaps, concrete)

1. A real read path from adport to the engine: an engine `ReadProvider` backed by adport's normalized `report`/`accounts_list` tools (server-to-server, per-organization token), so analysis and proposals are about the tenant's accounts; alias bindings should be derived from `organization_ad_accounts`, not hand-inserted SQL.
2. Per-organization engine identity (one `PAID_MEDIA_API_TOKENS` entry per org or a signed caller header) so thread ownership and proposals are isolated inside the engine too, not only in `markting_threads`.
3. Expiry handling for approvals: a sweep that marks `markting_engine_proposals` expired, a visible "expired" state on the Approvals page, and a re-preview button; a configurable TTL for human-speed approvals.
4. Repository-level CI: run `make test`, all 14 package suites, the full cloud suite against a CLI-started Supabase, the upstream engine suite (`uv run pytest`), ruff/mypy, `tsc`, and a `check-upstream-edits` diff against the SHAs in `UPSTREAM.md`.
5. Container builds and a smoke test (`seed → login → chat → pending → apply`) executed somewhere with network access; the stack has never been built as containers (`PHASE1-REPORT.md:74`).
6. Alias and provenance management UI (map engine aliases to accounts, browse threads, see translation notes), currently only reachable via SQL/seed.
7. Arabic/RTL engine reports (forked Jinja templates + Arabic font in the image) and Arabic-aware number/currency formatting (SAR).
8. A boot-time consistency check tying `MARKTING_ALLOW_SELF_APPROVAL` to demo mode and refusing non-sandbox alias bindings while the engine is fixture-only.
9. Upstreaming the two engine changes the host needs (`write_provider` override, public checkpointer helper) so `services/engine-demo` stops depending on private symbols.
