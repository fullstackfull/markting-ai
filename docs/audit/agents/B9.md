## Findings

Consolidated, deduplicated team findings are in `docs/audit/10-data-attribution-audit.md`
(and in the structured JSON). This section records only the lead's own spot-check
outcome: **15 spot-check groups covering roughly 30 distinct citations across B1–B8,
A12, A13 and A15 — every one reproduced exactly as written.** No specialist citation
was found to be wrong, mislocated, or overstated against the code. Two clarifications
surfaced:

### B9-SC1 — The "empty dict vs None" nuance in the reconciliation tautology is real and harmless to the conclusion
- Classification: VERIFIED_CODE
- `reads.py:266` sets `provider_totals = result.payload.get("totals") or {}` (an **empty dict** for live reads), while `compute.py:225` guards with `if provider_totals is not None`. An empty dict is not `None`, so control enters the block — but `provider_totals.get("spend")`/`["row_count"]` are then `None`, so both provider checks are skipped. Net effect is exactly what B1-01/B8-03 claim: for live data only the tautological `entity_rows_sum_to_platform_spend` check runs. The nuance does not change the verdict; `reconciled=yes` for live data means "our sum equals our own sum."

### B9-SC2 — The cross-platform-total mitigation is asymmetric between surfaces
- Classification: VERIFIED_CODE
- `compute.py:406` exposes only `spend` on the model-facing `AnalysisSummary.cross_platform_total`, but `render.py:123-134` renders the **full** scorecard (conversions/CPA/ROAS) into the PDF/HTML, with the "own attribution / not deduplicated people" caveat appended to a `data_quality` footnote only when more than one platform is present. So A13-01/B2-02/A12-04 are all correct and non-duplicative: the blended conversions/CPA/ROAS reach the human report (caveated in a footnote), not the model's structured summary. This is why I kept the finding at P2 rather than downgrading it on the "spend-only summary" mitigation.

## What a world-class system would need (gaps, concrete)

See `docs/audit/10-data-attribution-audit.md` §4 (T0–T5 trust ladder) and §5 (the
recommendation-confidence contract). In one line: a single canonical metric contract
enforced by both engines; an `Attribution` descriptor carried on every row and used to
gate blended totals; a live `data_complete_through` per platform; a tri-state
reconciliation requiring an external oracle; a deterministic data-sufficiency gate on
`propose_change`; and store-verified revenue before any "profit"/"incremental" wording is
permitted.

## Disagreements / claims in docs that the code contradicts

Consolidated in §6 of the main audit. The sharpest, each verified by me:
- `tools/reports.py` advertises a "reconciled report" and `render.py:174` prints "all sources complete and reconciled," but `reconciled` is hardcoded `True` and tautological for live data.
- `compare_periods.py:140` promises a cross-platform total "only when sources are compatible," but "compatible" never checks attribution or timezone.
- `metrics-and-attribution.md` forbids adding conversion counts "as if deduplicated people," yet `compute.py:278-298` does exactly that into the rendered scorecard.
- `reporting-semantics.md:13,15` ("missing stays absent"; "never sum across currencies") vs `live-data.tsx:33-41` (sums across currencies) and six providers coercing missing→0.
- The wiki tells the model "last N days" ends at `data_complete_through`, which no live path ever sets.
