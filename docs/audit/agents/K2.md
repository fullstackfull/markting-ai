## Recommended target AI architecture (decisions with rationale, not implementation)

I adopt 03's five-part shape and ratify it as the council's architecture, with the sequencing
constraint that **the safety gate precedes any live enablement**. The engine is a vendored
byte-identical import (`UPSTREAM.md`), so markting logic lives in `services/engine-demo`, a sidecar,
or `platform/`, and the engine is extended through its seams (`build_agent_components(system_prompt=…)`,
`init_chat_model` base_url/key), never forked.

1. **AI Gateway (prerequisite plumbing).** *Decision:* ship the markting-owned safety items
   unconditionally (boot readiness check, `MARKTING_ALLOWED_MODELS` allowlist, ordered provider
   fallback, a usage ledger keyed by org from the `thread_id` prefix, ephemeral prompt caching on the
   stable prefix + last message, a run-level wall-clock deadline, a per-thread lock + idempotency key,
   OTel/trace id minted at the cloud edge, typed localized failures). Adopt a **self-hosted
   OpenAI-compatible gateway (Option B)** when live mode goes multi-tenant, because it is the only
   option that keeps vendor keys out of both app containers and gives per-org budgets, fallback and
   circuit-breaking without engine edits; accept the portable-selector cost (one extra cheap call per
   turn when `base_url` is set, `tool_selection.py:166-167`). Keep the managed gateway (Option C) for
   internal model evaluation only until KSA data-residency is cleared. *Rationale:* every control
   above is a prerequisite for connecting real data and billing; they live entirely in markting code;
   routing/quotas/caching are the levers for cost and reliability (K2-P2-01/02/03).

2. **Intelligence layer (the ontology the model reasons over).** *Decision:* a tenant-scoped,
   versioned, provenance- and currency-carrying ontology owned by **adport** (where tenancy, RLS,
   retention and provider reads already live), surfaced to the model as a **bounded per-turn context
   block plus tenant-isolated retrieval tools** — never a shared folder, never a model argument for
   `organization_id` (bound server-side from the thread prefix, `repository.ts:12-14`). Deliver the
   brief through a **new engine `context` field** on `MessageIn`, not concatenated into user prose, so
   injected ad data is never confused with instructions. Structured SQL+FTS first; pgvector only for
   unstructured corpora (brand books, creatives), hybrid with Arabic normalisation, filtered
   `organization_id IN (NULL, $org)`, cited. *Rationale:* closes K2-P1-03 and the DATA/DIAGNOSIS
   grounding gap; keeps tenancy a server-side fact (closes the account-scope class, K2-P2-06); avoids
   the shared-folder isolation holes by construction (K2-P1-04).

3. **Marketing memory.** *Decision:* facts (`markting_memory_facts`, status ∈ {proposed, confirmed},
   only confirmed/reviewed facts injected) + account baselines + decision outcomes + immutable audit,
   all in adport Postgres; the engine stays stateless per tenant except checkpoints; **the model may
   propose a fact, a human confirms it; no learned value ever changes a policy limit, approver set,
   or protected-account list.** Fix the lifecycle first: per-org workspace/report/history roots,
   a deletion-route call into an engine purge, retention extended to `markting_*`/memory/engine
   tables, TTL on `pma_dedupe`, and a `handed_off` engine decision instead of `reject`. *Rationale:*
   closes K2-P1-04/05 and K2-P3-03 and GAP-01 while keeping learning governed and revocable.

4. **Recommendation pipeline.** *Decision:* adopt the explicit stage pipeline DATA → VALIDATION →
   NORMALIZATION → SIGNAL DETECTION → DIAGNOSIS → RECOMMENDATION → RISK → POLICY PREVIEW → HUMAN
   APPROVAL → EXECUTION → OUTCOME → LEARNING, and converge on **one** human-gated, metered, observable
   write path. Concretely: enforce an out-of-band approver on **every** apply surface (REST/MCP, not
   just the dashboard) — this is the single most important fix (K2-P1-01); **mirror the engine's
   `classify_risk` on the adport write path** and route high-risk to mandatory human apply;
   **retire or default-gate the generic `*_api_*` tools from the tenant/agent runtime** (K2-P1-02);
   make apply atomic (`… where consumed_at is null returning *`) with an idempotency key, and re-check
   budget policy at apply, not only validate (K2-P2-04/P3-02); add deterministic `explain_delta`,
   significance, and creative/frequency signals (GAP-03). *Rationale:* the VALIDATION, POLICY PREVIEW
   and the engine halves of RECOMMENDATION/RISK/EXECUTION are already strong; the load-bearing gaps
   are DATA, DIAGNOSIS grounding, HUMAN APPROVAL on autonomous surfaces, OUTCOME and LEARNING — an
   "AI media buyer" is exactly the sum of the missing stages.

5. **Outcome loop.** *Decision:* a `markting_decision_outcomes` table (org-scoped, RLS) seeded from
   `markting_engine_proposals` + the engine's `measurement_plan`; on apply write `before`+`expected`+
   `measure_at`; **invoke the pending sweep that already exists but is never called**
   (`repository.ts:420-425`) to set `expired` and, at `measure_at`, read the maturation window, write
   `after`, compute a `verdict`, and inject the last-N verdicts into the next turn's brief. Governed
   learning only from (a) user-confirmed facts, (b) measured outcomes of applied decisions, and (c)
   accept/reject rates used to annotate/rank proposals — never to change a limit, approver, or
   protected list. *Rationale:* this is the loop that turns suggestions into a system that improves;
   without it the "media buyer" cannot learn (GAP-01).

**Sequencing decision:** (1) safety gate — close K2-P1-01/02/04/05 and P2-04/07 before any live
read/write beyond one trusted org; (2) gateway safety items; (3) connect the brain (intelligence +
memory + Arabic/regional doctrine); (4) pipeline completion (signals + intent-aware demo); (5)
outcome loop + Workbench + eval-in-CI with a provenance/hallucination grader.
