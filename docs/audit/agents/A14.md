# A14 — Creative strategy expert

Audit question: does MARKTING-AI understand creatives at all (inventory, hooks/angles/offers/CTAs, landing pages, fatigue, winner detection, clusters, lifecycle, testing), and what would a Creative Intelligence subsystem need?

Short answer, verified against code: **No.** The product has no creative entity, no creative attributes, no creative-level consumer, and no creative signal (reach/frequency). The vendored adport layer can return *ad-level* metric rows for 9 of 11 providers, but those rows carry only `id/name/status` plus the ten account-level metrics, and every markting surface (dashboard, audit pack, sandbox, engine fixtures, bridge) queries at **campaign** level only. The engine's prompt wiki tells the model to "consider creative fatigue" and names a `get_creative_performance` tool, but no such tool exists in the catalog the product ships, and the data model cannot carry the inputs fatigue needs. The upstream engine's own eval expects the honest answer "creative-level data is not available" (`engine/tests/eval/questions.json:8`).

## Findings

### A14-01 — No creative entity, attribute, or storage exists anywhere in the product
- **Severity:** GAP (not a defect: nothing claims to provide it)
- **Classification:** VERIFIED_CODE / MISSING
- **Evidence:**
  - `platform/packages/core/src/model.ts:15` `ENTITY_LEVELS = ['account','campaign','ad_group','ad']`; `:43` `entity: { level; id; name; status? }` is the entire entity shape; `:1-12` `METRICS` has ten metrics, none of them reach or frequency.
  - `platform/supabase/migrations/*.sql` (30 `create table` statements, command #6): no table for ads, creatives, assets, headlines or landing pages. `engine/src/paid_media_agent/persistence/postgres.py:12-39`: only `pma_proposals/approvals/receipts/dedupe/thread_owners`.
  - `engine/src/paid_media_agent/domain/metrics.py:49-66` `PerformanceRow` fields: platform, account_ref, entity_type, entity_ref, entity_name, window, currency, spend, impressions, clicks, conversions, conversion_value, source_fields, quality_flags. No format, text, media, URL, reach, frequency.
  - Commands #1-#4: zero hits for `headline` (as ad text), `landing page`, `UGC`, `hook`, `angle`, `CTA`, `fatigue` as code.
- **Description:** The system models an "ad" as an opaque id with a name and ten aggregate metrics. There is no notion of what the ad *is* (image/video/carousel/RSA), what it *says*, where it *sends* people, or how often it is *shown* to the same person.
- **Impact:** Every creative-strategy question (which hook wins, which asset is fatigued, which landing page converts) is unanswerable from first principles; the Assistant can only answer at campaign granularity.
- **Recommendation:** Treat as the foundation gap for the design in the last section. Do not add creative prose to prompts before the data exists (see A14-03).

### A14-02 — Ad-level report rows exist in adport for 9/11 providers but are ID-only for several and unreachable from every markting surface
- **Severity:** GAP
- **Classification:** VERIFIED_CODE (+ VERIFIED_TEST for Meta/LinkedIn/X/Pinterest/core) / EXISTS_BUT_LIMITED (adport) → MISSING (markting UI)
- **Evidence:**
  - Supported: Meta `platform/packages/meta/src/provider.ts:165-224` (`ad_id, ad_name`); Google `google/src/provider.ts:166,222-224` — ad entity name is the literal string `` `ad ${id}` `` (no ad name, no headlines selected); TikTok `tiktok/src/provider.ts:104` (`ad_name`); Snapchat `snapchat/src/provider.ts:15,77` — `name: stat.id` (ID only); LinkedIn `linkedin/src/provider.ts:84-85,108` — pivot `CREATIVE`, name falls back to `entityId`; X `x/src/provider.ts:97-110` — synthetic names "Promoted post {tweet_id}" / "Media creative {id}"; Reddit `reddit/src/provider.ts:53,244` — `name: entityId`; Pinterest `pinterest/src/provider.ts:101` (`entity.name`); Spotify `spotify/src/provider.ts:15,95` (`entity_name`).
  - Rejected: Microsoft `microsoft/src/provider.ts:135-136` and Apple `apple/src/provider.ts:162-163` ("report supports campaign and account levels in v0").
  - Rejected in every synthetic path: `platform/packages/core/src/testing/synthetic-provider.ts:50` and `platform/apps/cloud/lib/markting/sandbox-provider.ts:101` ("support account and campaign levels only"); verified by test `core/test/synthetic-provider.test.ts:89` (command #7, exit 0).
  - Every markting consumer hardcodes campaign level: `platform/apps/cloud/lib/cloud/reads.ts:54` (`level: 'campaign'`), `platform/packages/core/src/audit/runner.ts:46`, `audit/tools.ts:47` ("campaign level").
- **Description:** The capability to pull ad-level metrics is upstream adport's, exposed through the MCP `report` tool (`core/src/tools/builtin.ts:61` default `'campaign'`). In the markting product nothing requests it, the demo cannot serve it, and for Google/Snapchat/Reddit/LinkedIn the row would be an anonymous id anyway.
- **Impact:** A user of the hosted dashboard or Assistant never sees an ad-level number. The "AI media buyer" cannot name the best or worst ad.
- **Recommendation:** Before any creative work, (a) make ad-level rows carry a real name and the parent chain (campaign → ad group → ad) for every provider, (b) extend the sandbox provider to an ad grain so the demo can show it, (c) surface it in the dashboard and audit runner.

### A14-03 — Engine prompts instruct the model about "creative fatigue" and a `get_creative_performance` tool that the shipped catalog does not have, and the data model cannot compute fatigue
- **Severity:** P3 (prompt/documentation promises exceed the data; the honest-refusal eval mitigates fabrication)
- **Classification:** VERIFIED_CODE / DOCUMENTED_NOT_IMPLEMENTED
- **Evidence:**
  - Prompt text: `engine/skills/paid-media-wiki/decision-model.md:35` ("Consider … creative fatigue, audience saturation …"); `bidding-and-budget.md:12` ("look at bids, audience size, approval status, or creative fatigue"); `paid-media-analysis/SKILL.md:31` ("`get_creative_performance` where the platform exposes it"); `platform-playbooks.md:16` ("ads own creative").
  - Catalog actually shipped: `engine/src/paid_media_agent/tools/fixtures.py:72-140` registers `list_campaigns`, `get_campaign_performance`, `get_ad_group_performance`, `get_campaign`, `update_campaign_budget`, `update_campaign_status`. No creative tool. Live mode in this product uses the same `configured_profile` with fixture fallback (`services/engine-demo/serve_demo.py:208`, `engine/src/paid_media_agent/runtime/mda.py:54-72`); a Pipeboard catalog could add tools but none is configured here (NOT_VERIFIED for a live Pipeboard deployment).
  - Fatigue inputs absent: `PerformanceRow` (`domain/metrics.py:49-66`) has no reach/frequency; Meta insights field list is hardcoded to `spend, impressions, clicks, actions, action_values` (`platform/packages/meta/src/provider.ts:168-174`).
  - The only "flag" logic is day-over-day spend/conversion movement ≥ a threshold (`engine/src/paid_media_agent/tools/summary.py:28,118-126`); `_attention_lines` ranks by absolute spend delta only (`tools/compute.py:349-372`).
  - Upstream's own eval encodes the limitation: `engine/tests/eval/questions.json:8` q07 expects "honestly states creative-level data is not available".
- **Description:** The model is told to reason about creative fatigue and to look for a creative tool, but the product gives it neither the tool nor the metrics. In demo mode the scripted model never reaches this text; in live mode an LLM may hypothesize fatigue with no evidence.
- **Impact:** Risk of plausible-sounding creative explanations ("CPA rose because of creative fatigue") that cannot be grounded. Mitigated by the wiki's "do not guess" rules, but unverifiable here.
- **Recommendation:** Either ship the data (A14-02 + frequency) or scope the prompt: state that creative grain and frequency are unavailable in this deployment so the model refuses rather than speculates.

### A14-04 — The `low-ctr` audit rule promises creative diagnosis it cannot make
- **Severity:** P3
- **Classification:** VERIFIED_CODE
- **Evidence:** `platform/packages/core/src/audit/packs/core-performance.ts:35` ("Flags campaigns whose creative/targeting is not resonating"), `:47` ("Review creative and audience targeting; test new headlines/assets"), `:25` ("rework targeting/creative"); runner grain `audit/runner.ts:46` is `campaign`; rule input is `ctx.rows` of `ReportRow` with no creative attributes.
- **Description:** A campaign-level CTR threshold (`low_ctr_threshold_pct: 0.5`, `:122`) is relabeled as a creative finding. Nothing distinguishes "bad creative" from "bad audience", "wrong placement" or "brand vs non-brand mix".
- **Impact:** Findings page text steers users toward creative changes on no creative evidence; low severity because the rule is explicitly a heuristic and proposes no automatic action for this rule.
- **Recommendation:** Reword to "low CTR (cause undetermined)" until ad-level rows and creative attributes exist; then split the rule into per-ad CTR dispersion inside an ad set.

### A14-06 — Creative publishing paths exist with only generic guardrails; no creative-specific policy
- **Severity:** GAP (classification UNSAFE_TO_AUTOMATE for creative publishing); not reachable from the markting bridge
- **Classification:** VERIFIED_CODE
- **Evidence:**
  - Typed: `google_create_responsive_search_ad` (`platform/packages/google/src/tools.ts:141-154`) validates only counts/lengths and `z.string().url()`; `provider.ts:839-849` `validateRsa` (3–15 headlines ≤30 chars, 2–4 descriptions ≤90 chars); created PAUSED only when `guard.forcePausedCreation` (`provider.ts:636-638`).
  - Generic: `meta_api_create` accepts any edge incl. `adcreatives`/`ads` with arbitrary fields (`meta/src/tools.ts:193`, `provider.ts:343-370`); paused coercion applies only to `campaigns|adsets|ads` (`:351`), creatives have no status so pass untouched. - **Recommendation:** Any Creative Intelligence subsystem that proposes new creatives needs a creative-specific policy layer and a rendered preview before the existing pending-operation gate (see design).

## What a world-class system would need — Creative Intelligence subsystem (design only)

### 1. Entities (new, tenant-scoped, under adport's existing RLS pattern)

| Entity | Key fields | Notes |
| --- | --- | --- |
| `creative_asset` | id, org_id, provider, account_id, provider_asset_id, kind (image/video/carousel_card/text/html5/audio), media_url (encrypted ref or proxied), sha256, width/height/duration, language, detected_text (OCR/ASR), thumbnail_ref, first_seen, last_seen | Immutable per hash; Apple already binds SHA-256 on upload (`apple/src/tools.ts:150-153`) — reuse that idea for provenance |
| `creative` | id, org_id, provider, account_id, provider_creative_id, ad_id(s), format (RSA/PMax asset group/single image/video/collection/story/spark), primary_text, headlines[], descriptions[], cta_type, display_url, final_url(s), utm, status, policy_review_status, created_at (provider), last_modified | One `creative` can serve many `ad`s (Meta `adcreatives` reuse); one RSA is one creative with N headline assets |
| `creative_annotation` | creative_id, taxonomy_version, hook_type, angle, offer_type, proof_type, cta_style, persona, emotion, visual_style, language_variety (MSA / Gulf / Egyptian / Levantine), has_price, has_urgency, has_person, brand_safety_flags | Produced by a classifier (LLM + rules), **versioned**, never overwrites — append new versions |
| `landing_page` | url_canonical, org_id, last_crawled, status_code, ttfb_ms, lcp_ms (if measurable), lang/dir, title, h1, price_found, cta_count, forms, pixel/tag presence (Meta pixel, GA4, TikTok, Snap), message_match_score (vs creative text) | Crawl only with tenant consent and robots respect; store text hash not full page |
| `creative_daily` | creative_id, ad_id, date, spend, impressions, reach, frequency, clicks, outbound_clicks, video_3s/thruplay/25-100%, hook_rate (3s views / impressions), hold_rate (thruplay / 3s), conversions by event, conversion_value, ctr, cpa, roas, quality/engagement/conversion rankings (Meta), impression share (Google) | Extends `PerformanceRow` with a per-ad grain and the missing engagement metrics; currency-scoped like today (`report-summary.ts:9-12`) |
| `creative_lifecycle` | creative_id, stage (draft/pending_review/learning/scaling/plateau/fatigued/retired/rejected), entered_at, evidence_ref | State machine driven by signals below; transitions are **recommendations**, never auto-applied |
| `creative_experiment` | id, hypothesis, variants[], primary_metric, min_sample, start/end, allocation, status, result (effect, CI, decision) | Backs testing; ties to adport pending operations for the launch/pause writes |
| `creative_cluster` | id, method_version, centroid_ref, members[], label | From text+visual embeddings; label by dominant annotation |

### 2. Signals (all computed by code, surfaced to the model as artifacts, following the engine's "model does not do arithmetic" rule, `decision-model.md:29-31`)

- **Fatigue:** per creative, rolling 7d vs prior 7d: frequency ↑, CTR ↓, CPM ↑, hook_rate ↓, with minimum impressions threshold per tenant (no universal thresholds, per `goals-and-economics.md:34`). Output a fatigue score with the exact inputs cited.
- **Winner / loser detection:** within an ad set / ad group (same audience, same budget owner), compare creatives on the tenant's primary metric with a Bayesian or sequential test; report posterior probability of being best, not a verdict. Require minimum conversions.
- **Hook & angle performance:** aggregate `creative_daily` by `creative_annotation` (hook_type, angle, offer) across the account; report lift vs account baseline with sample sizes.
- **Message match:** creative final_url → landing_page; flag mismatches (creative promises discount, page shows none; Arabic creative → English page; RTL broken).
- **Diversity / saturation:** share of spend in the top cluster; too few clusters live = concentration risk.
- **Lifecycle transitions:** learning (age < N days or < M conversions) → scaling (winner probability > p for k days) → plateau → fatigued (fatigue score) → retire candidate. Each transition emits a proposal with before/after and a reversal plan, routed through `markting_engine_proposals` → adport preview.

### 4. Safety

1. **Read-only first.** Phases 1-3 (inventory, metrics, signals) require no new write tool. The existing invariant — proposals only, one write path through adport's policy engine (`README.md`, `translate.ts:65-69`) — must hold.
2. **Creative writes are a separate policy class.** Before `pending_operations`, add creative-specific checks: rendered preview (image/video thumbnail + text in RTL), landing page reachable and language-consistent, brand-term allowlist, prohibited-claims denylist (health, finance, religion-sensitive content for KSA/Gulf), character limits per provider, asset provenance (SHA-256 as Apple does), and **paused creation enforced for ads and creatives alike** (today `adcreatives` escape `forcePausedCreation`, `meta/src/provider.ts:351`).
3. **No automatic pause/retire.** Fatigue and loser signals create proposals with minimum-evidence gates (impressions, conversions, days) and a reversal plan, consistent with `write-safety.md:24`.
4. **Media handling.** Store references and hashes, not copies, unless the tenant opts in; strip EXIF/PII; never send tenant creatives to third-party models without the tenant's explicit setting; log every classifier call in `audit_events`.
5. **Tenant isolation.** Every new table under the existing org-scoped RLS; aliases never leak provider ids to the model (`reads.py:103-106` pattern).
6. **Honesty contract.** When a provider lacks a signal (e.g., Reddit has no frequency), the artifact says `unavailable`, never zero (`metrics.py:1`), and the model's answer carries the gap — extend eval q07 to one question per signal.
7. **Arabic specifics.** Classifier must handle MSA vs dialect, mixed-direction text with Latin brand names, and detect broken shaping in rendered previews; landing-page crawl must verify `dir="rtl"` and Arabic font loading.

### 5. Build order (smallest honest increments)

1. Make `ad`-level rows real (names + parent ids) for all providers; add reach/frequency/video metrics to `METRICS` as optional (null when unavailable). Extend sandbox + engine fixtures with per-ad series.

5. Proposals for pause/scale/retire through the existing bridge, extending the allowlist beyond campaign budget/status with the creative policy class from §4.2.
6. Only then: creative generation (text variants, asset briefs), always as drafts requiring human publish.
