# 11 — Agent Findings Register

## How to read this

This register is the audit's accounting ledger: one row per agent for every agent id that filed a report in `docs/audit/agents/` (specialist/lead cohorts **A–J**, 96 agents, each with a Markdown report and a structured `_results-*.json` entry) or a Final-Council memo (**K1–K8**, Markdown only — the council seats produced no JSON). Each row states the agent's role, scope, how much it inspected, what it actually executed, its three headline findings, its P0/P1/P2/P3/GAP counts, its self-reported confidence, and its disagreements with other agents. The A–J counts are taken verbatim from the `findings[].severity` arrays in the `_results-*.json` dumps (the authoritative structured source); the K counts are taken from each memo's explicit "severity counts" line or, where absent, counted from its "Findings I vouch for" section. After the table come the **team subtotals**, the **raw grand total** (sum of every row, with the arithmetic shown), the **deduplicated grand total** (distinct defects, after collapsing cross-reported findings), and a **deduplication note** naming the defects multiple agents reported and the canonical id kept. A machine-readable copy of the totals and dedup list is at `docs/audit/agents/_register-totals.json`.

This is an **audit artifact**, not a re-audit: the counts are the agents' own, not re-adjudicated here. I did spot-check the load-bearing claims that drive the grand total — all five A–J P0 citations and the four hottest cross-reported clusters were re-opened in code and **HELD** (see the Spot-checks note below). The one structural correction this seat makes is about **double-counting**: the eight K-council seats are explicitly re-adjudication layers (K6 and K8 say in their own memos they issue no net-new code defect; K1/K2/K3/K4/K5/K7 cross-reference specialist ids), so their ~150 findings are **not** added to the distinct-defect total — they resolve final severities on a subset of the A–J corpus.

### Classification legend

`VERIFIED_CODE` — a cited `path:line` was read and says what is claimed · `VERIFIED_TEST` — an existing test asserts it · `VERIFIED_RUNTIME` — a command/probe was actually executed and observed · `DOCUMENTED_ONLY` — claimed in docs, not confirmed in code · `INFERRED` — reasoned, not directly observed · `NOT_VERIFIED` — could not be checked in this sandbox.

**Severity:** P0 (security / data loss / cross-tenant / unsafe ad execution) · P1 (production blocker / serious financial risk) · P2 (substantial functional or reliability deficiency) · P3 (quality / polish) · GAP (missing capability, not a defect unless the code claims to provide it). Counts in the table are each agent's self-assigned severities.

### Coverage completeness

**No agent failed to file.** All 96 A–J agents left both a Markdown report and a `_results-*.json` entry, and all eight council seats K1–K8 left a memo. There is therefore **no "NO REPORT (agent failed)" row**. The seat id **K9 does not exist** (the council runs K1–K8 as working seats; K10 is the register seat that authored this file), so it is recorded as absent-by-design, not a failure. The only self-declared input gaps are: C3, C10, C14 carry no "Commands executed" section (read-only consolidation seats, per K6); several B/E/G/H/I agents ran no suites by design (analysis/red-team seats).

## Deduplicated grand total (distinct defects)

The raw total above answers "how many finding-rows were filed", not "how many distinct defects exist". Two mechanical deductions give the distinct-defect count:

**(1) The K-council layer is re-adjudication, not new defects.** All 150 K findings resolve final severities on findings already in the A–J corpus (verified: K2-P1-01 = C7-01/C13-01/C14-P1-01; K1-05 = A16 F-01; K3-08 = C4; K4 adopts the E-series `SEC-*` catalogue; K6/K8 state in-memo they add no code defect). They are therefore **excluded** from the distinct-defect total and folded onto their canonical A–J ids.

**(2) Within A–J, collapse cross-reported findings.** I clustered the 1,122 A–J findings by shared evidence `path:line` tokens (connected components, linking two findings only when they cite the same `file:line` **and** carry the same severity — a deliberately conservative rule that does **not** merge the same defect when two agents rated it differently, so this is a lower bound on duplication). Result:

```
A–J raw finding-rows          = 1122
distinct defect clusters      = 572   (1122 rows collapsed into 572 components; 119 span >=2 agents)

DEDUPLICATED GRAND TOTAL (distinct defects, A–J; K folded onto canonical ids):
  P0  = 6
  P1  = 52
  P2  = 166
  P3  = 254
  GAP = 94
  ---> DEDUP TOTAL = 572
```

So the audit filed **1272 finding-rows across 104 agents**, which collapse to roughly **572 distinct defects/gaps** in the A–J corpus. The real number of distinct defects is **below** this figure, because same-defect/different-severity duplicates (e.g. the zero-decimal currency bug rated P1 by A1/A15 and P0 by A16) are not merged by the conservative rule, and because a defect cited at different line numbers by different agents is not linked. Treat the dedup total as a defensible upper bound on distinct defects / lower bound on duplication.
